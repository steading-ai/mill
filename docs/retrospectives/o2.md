# Retrospective: O2, isolated

**Date:** 2026-09-12
**Scope:** the O2 milestone (`mill#53`): a run's sessions execute inside a `systemd-nspawn` machine the worker starts without root, imaged from the repository's `mill.toml`, cached from btrfs lineages, reaching out only through the host's proxy and the credential gateway; the live tier run once on the host by a person and then by mill inside its own machine.

Two voices. Ivy's is the operator's, written from the record — the harness report, skift's timeline, the journal, homestead's incident log — not from a conversation; Claude's is the agent that worked the milestone's last node, moved the deployed worker into its machines, and watched it deliver the proof.

## What was built

The design first: `docs/sandbox.md`, `docs/sandbox-scenarios.md`, ADR-018, the roadmap reordered (`mill#55`). Five spikes on `core` before any backend code — a machine booted through polkit from the operator's uid, a session answering through a host gateway, egress through squid only, a machine inside a machine, cache lineages by snapshot (`mill#73`–`#77`). Then the backend: the workspace selector and the driver seam, the credential gateway, `mill.toml`, images by digest, cache lineages, the machine's lifecycle, exec under a step slice, reconciliation, preparatory steps that degrade into findings, the skill mount, `nested`, eviction, the foreground wait, the ledger's sandbox row, git and forge verbs run on the host, the session spawned inside the machine (`mill#56`–`#68`, `#80`–`#82`). Two bugs found on the way and fixed as nodes (`mill#79`, `#83`). The end-to-end node (`mill#69`) ran the live tier on `core`, the documents caught up (`mill#70`), and this node moved the deployed worker into its machines, gave the mill project workflows of its own with the live tier as a check step (`workflows/mill-quick-fix`, `workflows/mill-feature`), and had the worker deliver one node there with that step at exit 0. On the host side, five homestead roles (`mill_storage`, `mill_machine`, `mill_selinux`, `mill_egress`, `mill`) carry what mill cannot provide for itself.

## Claude's side

### What worked, and why

- **The spikes paid for themselves.** Five spike nodes, $44 between them, before the first line of backend code. The nested spike found E13 — that an inner nspawn needs a fully visible `/proc` and `/sys` in its tree when it pivots — and the privilege spike found E7, that an unprivileged outer does not boot on `core` at all. Both would have been week-long surprises inside a build node. The pattern from O1 held: run the experiment as its own node with its own result, and let the build nodes cite it.
- **Findings, not failures.** The design's rule that a preparatory step, a `mill.toml` error or an ungranted `nested` request becomes a finding the first session receives — never a failed run — is why the proof run could be filed three times in forty minutes and each filing told its implementer exactly what the last one hit. The parked run's gate carried the implementer's own diagnosis of the missing `workflow-dir`, with the file and line, before I had read the code.
- **Reconciliation earned its node.** Every abandoned generation left a machine and a run directory behind, because `mill restart` does not know the machine backend (below). Every one was swept at the next worker start: `reconcile: orphan mill-01m29qfxqdbabv5kab62q8wpsa: stopped; run directory removed`. The host was clean after every misstep without a hand on it.
- **The check sent the session back, and the session fixed the tree.** The fourth filing's body dictated three edits; the `live-tier` step then failed twice on things nobody had dictated — a privileged reaper crun will not start inside a machine, a sidecar spec that read the gateway's variable as a leak, two `internal/cli` specs writing into the real home — and `on_failure: revise implement` handed the session ginkgo's report as its next prompt. Fifty-eight minutes later the tree passed its own tier inside the machine, and the ledger shows the two failed attempts, the superseded first commit and the second one that merged. That is the workflow doing what §Step says a check is for, on the first node that ever had a check with teeth.
- **The ledger held the whole story.** Three generations of `mill#84`, the aborted assessment, the 118 refused resumes, the check that never ran and the one that exited 203, the unsigned commit the push refused — all of it is in `mill inspect --view full`, and the retrospective's numbers came from there and from the journal, not from memory.

### What I would do differently

- **Step 0 was never run inside a machine before the proof.** The acceptance suite passes `--workflow quick-fix`, so the assessment step — the one every real run starts with — had never been exercised on the machine backend. It ran outside the step boundary (a machine refuses an exec under no slice) and never installed its token in the gateway (the session's every request was refused as "not a live step token"). Two one-screen fixes, both in `internal/run/select.go`, both with a spec that fails without them; but the proof node was the first thing to reach them, in production. The lesson is the O1 one again: drive the deployed system as the principal the vision describes, and do it with the defaults, not the flags the suite prefers.
- **A failed run is reclaimed at once, forever.** When the assessment failed instantly, the worker released the lease as a crash, skift handed the node straight back, and the worker claimed it again: 119 claims and 121 assessment attempts in fifty-two seconds, and after the fix for that step's slice, 118 refused resumes in ninety-four. Nothing in mill or skift backs off. The breaker parks a step that fails repeatedly *inside* a run; a run that fails before its first step has no breaker. That is a design gap for O3.
- **The deployment drifted from the tree in three ways at once.** The store held the commit and pr skills from before `mill#69` (the role's push task never ran after the apply failed early), so a session was told to `git commit` itself and the push refused the unsigned result; the configuration had no `workflow-dir`, so `scripts/clean-tree` could not be resolved; and the binary lagged six nodes behind `main`. Each is a homestead finding, and each was found by the proof rather than by `mill doctor`, which probes none of the three.
- **`mill restart` is local-only.** It attaches `attachedWorkspaces(opts.workspaceDir)` whatever `workspace:` says, so under the machine backend it abandons the run and leaves the machine; and it leaves the park gate's `blocks` edge in place, so the new generation is unclaimable until a person unlinks it — which skift's model says a dropped gate never satisfies. The gate's own text ("Drop it, or run `mill restart`") is wrong on both counts.
- **The commit verifier checks identity, not signature.** A plain `git commit` inside the machine, as `agent` with the mill's name and email, closed the commit step; only the push, one step later with no `on_failure` back to commit, refused it. The verifier should refuse what the push will.
- **I deployed an unreviewed binary, twice.** The proof could not happen on `main`'s binary — the assessment fixes above are in this tree and nowhere else — and the work order forbade delivering it through the harness, so the deployed worker ran a build of this working tree: forty minutes for the third filing, and again for the fourth. The result says so each time; the homestead apply between them put `main` back; the fixes reach the deployment when this node merges. It was the only way to a proof, and it is not a pattern.
- **The tree had to change before the check could pass on it, and the tree the check runs on is `main`.** A check step that runs `MILL_SANDBOX_HOST=1 make test` inside a flat machine on `main` as it stood failed on two things: one live spec hard-coded the host's `/var/lib/mill`, and the cache specs need `btrfs-progs`, which no image of mill's carried because no `mill.toml` declared it. The fixes were in this working tree, which merges only after the proof. So the proof node carries them: its body dictates the two-line spec change, the `mill.toml` and a `.gitignore` line, tells the session to install `btrfs-progs` through the dnf shim first, and the `live-tier` step then runs the tier on the tree the session committed — which is the workflow doing what it is for. The check tests the change; the change is what makes the check runnable. It is the bootstrap's shape one more time, and the last time for this tier.
- **Inside a machine, the live tier is honest rather than whole.** `make test` with the tier on runs every spec of mill's inside the machine; the ones that need the host — the template unit, the host's podman, the subscription, a forge — read `/run/systemd/container` and skip naming what they need, and the cache lineage specs run for real on the ephemeral root under `/home/agent/mill`. What the exit 0 says is exactly that, and `mill logs <run> --step live-tier` says which was which. The design's fuller version — a spec that drives the inner boot from inside a nested machine, a `skift` the fixture can start from the bound checkout so the run-loop specs run inside — is two nodes, named in §Self-hosting.

### Open bets

- **`nested` in production.** `mill#66` booted a nested machine on `core` through the real helper, and this node's `mill.toml` asks for it. The first deployed run of a mill node after this merges is the first time the nested variant is built and booted by the worker rather than a spec.
- **The sandbox tests the sandbox.** The bootstrap gate is once by design. Inside a machine the tier is the specs that need no host — the cache lineages on the ephemeral root, the unit and db tiers entire — and the ones that need the host say so and skip. Whether that is still the tier the gate ran is the question O3 has to answer before it can retire the person; the two nodes named under §Self-hosting narrow the gap.

## Next run

1. Back off. A run that fails before its first step must not be reclaimed by the same worker at once: a delay, a cap, or a park with a gate, but not a loop.
2. `mill restart` under the machine backend: destroy the machine and finish the workspace row; unlink the park gate it abandons, or say in the gate's text that a person must.
3. `mill doctor` probes the deployment's drift: the store's workflow versions against the tree's, `workflow-dir` set and resolvable, the binary's commit against the checkout's.
4. The commit verifier requires the mill's signature, and the pr step's failure on an unsigned head revises commit.
5. Homestead: `workflow-dir` in the role's template; the workflows pushed on every apply, not only when the build task ran.
6. Widen the tier inside the machine: a spec that boots the inner machine from inside a nested one (§"Nested, exactly", steps 1–3, as `agent` through sudo), and a `skift` the skift fixture can start from the checkout bound at `/var/lib/mill/skift`, so the run-loop specs run inside too.
7. Homestead: `mill-quick-fix` and `mill-feature` in `mill_workflows`, so the project's own definitions are pushed with the org's.
