# Error returns between opening and ending an activity writer leak it

## Approach

Give each attempt one exit path that closes the activity writer and detaches
the verb sink whatever happens, instead of patching each `return err` site
individually. The work order asks for this explicitly ("one exit path per
attempt"), and patching each site one at a time is how the bug accreted in
the first place — a future early return would be forgotten again the same
way these were. `defer` is already this package's idiom for exactly this
shape of cleanup (`worker.go`'s mutex unlocks and goroutine bookkeeping), so
it is not a foreign pattern.

Rejected: a generic `withActivity(open, body)` combinator wrapping all four
call sites. The four sites do not share enough shape to justify it — one has
a case switch, one has a deliberate "leave it open" branch, one has a
multi-attempt retry loop — and forcing them through one signature would hide
the one genuinely tricky part (the exception below) behind a parameter
instead of showing it at the call site.

Four call sites, four different placements of the same idea:

- **`internal/run/walk.go`'s `step()`** — `step()` runs one attempt per call
  (the outer loop is in `walk()`, calling `step()` fresh each time), so a
  single `defer` scoped to the function is correct *except* for one
  Chesterton's fence: the `errAnswered` branch (currently ~line 262)
  deliberately returns with the writer left open, by design — comment: "The
  attempt stays open and the loop goes round: the next pass ... closes this
  very attempt on the answer." A `defer` registered before that branch would
  wrongly close it. Fix: register the defer *after* the `errReleased` /
  `errAborted` / `errAnswered` / fenced gauntlet is behind it (right before
  `recordInstalls`), which covers `recordInstalls`, `recordUsage`,
  `RevokeStepToken`, `postUsage`, `reviewed`, the pending-evidence branch's
  `AbortOpenStepRuns`, and — because their errors propagate up through
  `step()`'s own return — `closeStep`'s and `failStep`'s own leaked-before-
  their-`endActivity` gaps, without touching either of those two functions.
  The two sites *before* that gauntlet (`IssueStepToken`, `Rotate` — before
  `execute()` even runs, so none of the special branches are live yet) get
  two explicit `abortActivity(s); return ...` calls instead; adding them to
  the deferred region would require threading the exception through two more
  call sites for no gain.
- **`internal/run/gate.go`'s `resumeGate()`** — each of its two activity-
  touching cases (`STATUS_DONE`, `default`) ends in an immediate `return`,
  so a `defer` registered right after `reopenActivity` succeeds, once per
  case, is unambiguous. The `default` case's own `denyGate()` call is a
  separate function but its error propagates straight back through
  `resumeGate`'s `return`, so `resumeGate`'s defer catches `denyGate`'s
  `skift.Complete` failure too without `denyGate` needing its own defer.
- **`internal/run/revise.go`'s `failStep()`** — not named by the work order,
  but reached directly from the `walk.go` switch the order does name
  (`case default: return r.failStep(...)`), and it has the same defect: its
  own `FailStepRun` call can fail before reaching its `endActivity`. The
  writer is always open on entry (every caller opens or reopens it first),
  so a `defer` at the top of the function is unambiguous. Flagging this as
  in-scope-by-necessity rather than scope creep; a reviewer can veto it.
- **`internal/run/select.go`'s `assess()`** — genuinely different: its per-
  attempt body sits inside `for { ...; if retry { continue } }`, a real
  multi-attempt retry loop. A `defer` at the top of `assess()` would only
  ever protect whichever writer `s.activity` points to when `assess` finally
  *returns* — every earlier iteration's writer would still leak forever,
  since `openActivity` just overwrites `s.activity` without closing the
  previous one. Fix: wrap the per-iteration attempt body (from
  `openActivity` through the `underBoundary` call) in an immediately-invoked
  closure, so its `defer` is scoped to one loop iteration, i.e. one attempt.
  The closure captures `feedback`, `feedbackFrom`, `retry`, `assessment` by
  reference exactly as the existing `underBoundary` closure already does, so
  this is a wrapping change, not a data-flow change.

## Risks

- **The `errAnswered` exception is easy to get wrong.** If the `defer` in
  `step()` is accidentally registered *before* that branch instead of
  after, a spec exercising a gate answered on the spot would start failing
  (the writer would close when it shouldn't) — mitigation: the existing
  gate-resume specs in `gate_test.go` ("closes the gate step with the
  gate's result and continues, in one step run") already cover this path
  and will catch the regression immediately if broken.
- **`/proc/self/fd` counting is Linux-only and can be noisy** (background
  goroutines, the test binary's own transient fds) if run concurrently with
  unrelated fd churn. Mitigation: count deltas immediately before/after the
  single `Execute` call under test, not as an absolute count, and treat a
  small fixed slack (say, allow no growth rather than requiring an exact
  count) as the assertion, matching how flaky-resource assertions are
  usually written; if it proves too flaky in practice, fall back to the
  sink-detachment assertion alone and note the fd-count check as dropped.
- **`recordUsage`, `recordInstalls`, and `reviewed` all require staging
  specific attempt shapes** (non-empty usage, a reported install, a verdict
  step) before their failure can even be reached. This is the bulk of the
  work in steps 2-3 and could reveal the existing fixture helpers
  (`reviewer`, `answerer`, the scripted harness) don't expose quite what's
  needed, in which case a small fixture addition (not a redesign) is
  expected and in scope.
- **`assess()`'s closure extraction changes a function that already has
  dense, load-bearing comments** about resume/crash-safety ordering
  (`docs/ledger.md §Resume`). Mitigation: the extraction only wraps
  existing statements in a closure and a `defer`; it must not reorder any
  of the existing calls, and the diff should be reviewed line-by-line
  against the original to confirm nothing but control-flow wrapping moved.
- **Nothing here is known to be missing or blocked** — all fixture pieces
  referenced (`wrapWorkspace`, `watching()`/`releases`, `run.ReadActivities`,
  `failingStore`) already exist in the tree; this plan only extends them.

## Decisions

- **Structural (`defer`) fix over patching every `return err` site**: the
  work order's own "one exit path per attempt" phrasing, plus this
  package's existing use of `defer` for identical cleanup shapes elsewhere,
  made this the smallest option that actually satisfies the deliverable
  rather than just resembling it.
- **`internal/run/revise.go`'s `failStep()` included** even though not named
  by the work order, since it's reached from the exact `walk.go` switch that
  is named and shares the identical defect. Called out explicitly here so a
  reviewer can scope it back out if that's unwanted.
- **`gate.go`'s `file()`/`fileGate()` (the gate-filing helper) left
  untouched**: its failures already funnel through the existing `errAborted`
  sentinel into `step()`'s pre-existing explicit `abortActivity(s)` call at
  the `errReleased`/`errAborted` branch, so it already has a single exit
  path and is not part of this defect.
- **"Closed" proven by fd-count delta, "detached" proven by
  `ReadActivities` silence after a subsequent verb**: no in-process hook
  exists (or is added) to assert `s.activity == nil` directly from the
  external `run_test` package, matching this repo's stated preference for
  real, black-box, end-to-end specs over white-box state peeking
  (`support_test.go`'s own header comment). If the fd-count assertion
  proves unreliable in CI, the sink-detachment assertion alone is treated
  as sufficient evidence, since both `abortActivity` and `endActivity`
  close-and-detach in the same call — demonstrating detachment is strong
  evidence the same call closed the file.
- **`failingStore` generalized in place rather than duplicated per RPC**:
  one field-driven wrapper is less repetition than up to a dozen near-
  identical structs, and keeps `gate_test.go`'s existing usage source-
  compatible.
