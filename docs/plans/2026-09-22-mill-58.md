# Usage recorded after a reclaim is fenced under the old lease

## Approach

Make the gateway's usage recorder read the lease live from `state` at call
time, instead of capturing it once when the step is installed.

`rotateGateway` (internal/run/walk.go:369-386) builds a `gateway.Step` whose
`Record` closure closes over a local `lease := s.leaseID()` taken at install
time. `reclaim` (internal/run/heartbeat.go:103-123) updates `state.lease`
when the heartbeat wins the node back mid-attempt, but the closure has
already captured the old value and never looks again, so every gateway
usage write for the rest of the attempt is fenced. `state.lease` is an
`atomic.Pointer[string]` (run.go:443-454) precisely so it can be read
concurrently from another goroutine — the gateway's `Record` runs on the
reverse proxy's own goroutine (internal/gateway/gateway.go:340-357) — and
every other lease-consuming call site in the package (`breaker.go`,
`cancel.go`, `execute.go`, `gate.go`, `finish.go`'s `recordUsage`) already
reads `s.leaseID()` fresh at the point of the write. The gateway closure is
the only holdout; that's an oversight from mill#31 (`2a281b5`), which
updated every other call site in this pattern but never touched
`rotateGateway`.

Rejected: having `reclaim` re-install (`Rotate`) the gateway step with a
freshly baked lease. The work order names this as an acceptable option, but
it requires `state` to start carrying the active step/sr/token so `reclaim`
— which today only has `s *state` in scope — can rebuild a `gateway.Step`,
and it reintroduces the same bug class one layer down: the newly baked
closure would go stale again on a *second* reclaim during the same attempt
unless every reclaim path remembers to re-rotate. Reading the lease live
removes the caching entirely rather than re-timing when the cache is
refreshed, and costs one line instead of new state plumbing.

`mill status`/`mill cost` (internal/cli/read.go) render `GetTotals()` and
`GetGatewayTotals()` straight off the store's live summary/detail queries —
there is no separate cache to invalidate. Fixing the write is sufficient to
fix what those commands show; acceptance criterion 2 falls out of criterion
1 with no extra work.

## Steps

1. **Read the lease live in the gateway's Record closure** —
   `internal/run/walk.go`: in `rotateGateway`, delete the captured local
   `lease := s.leaseID()` and call `s.leaseID()` inside the `Record`
   closure itself, at the point it invokes `r.recordGatewayUsage`. Correct
   the comment above it (currently: "the recorder runs on the gateway's
   goroutines, so it carries the lease it was installed under rather than
   reading the run's state") to say the opposite: it reads `state`'s
   current lease on every call, safely, because `state.lease` is an atomic
   pointer built for exactly this cross-goroutine read (run.go:443-454).
   No signature changes to `recordGatewayUsage` (finish.go:54-70) are
   needed — it already takes a lease string as a parameter; only the value
   passed to it changes from a captured local to a live read.
   Proof: `go build ./...` and the existing gateway specs
   (`internal/run/gateway_test.go`) still pass unmodified — this step
   changes no observable behavior when there is no reclaim, since
   `s.leaseID()` read at call time equals the captured value for the
   lifetime of an attempt that never gets fenced.

2. **Add a test covering a reclaim mid-attempt followed by a gateway usage
   record** — `internal/run/gateway_test.go`: a new `It` in the existing
   "The credential gateway in the run loop" `Describe` block. Shape,
   following the two established patterns already in this package (the
   self-reclaim scenario in `run_test.go:159-202`, and the gateway
   round-trip scenarns in `gateway_test.go`):
     - Start a real gateway (`startGateway()`) and a held session
       (`fake.Script{Hold: true, Cancelled: ..., Do: ...}`) whose `Do`
       makes one gateway request, signals a channel that it is ready, waits
       on a second channel, then makes a second gateway request before
       returning (Hold keeps the turn open the whole time, exactly as
       `internal/harness/fake/fake.go:114-144` runs `Do` once before any
       event and before the Hold blocks).
     - Run with a short TTL/interval (`o.TTL = 12 * time.Second`,
       `o.Interval = 200 * time.Millisecond`, matching
       `run_test.go:164-168`) and `g.options` wired in alongside.
     - Once the "ready" channel closes, read the current lease
       (`f.leaseOf`), force its expiry (`f.expire`), and `Eventually` wait
       for the node's lease to change to something else non-empty
       (`run_test.go:180-184`'s self-reclaim pattern — nobody else claims
       the node, so the worker's own heartbeat wins it back rather than
       being fenced).
     - Close the second channel to let `Do` make its post-reclaim request,
       then end the turn (`f.cancelRun`, wait for `Execute` to return nil).
     - Assert: `f.inspect(ctx)`'s step detail for this step has
       `GetGatewayTotals()` of length 1 — `TotalsForStepRun`
       (internal/store/queries/usage.sql:23-30) groups by `(model,
       source)`, and the stand-in upstream reports the same `turnModel`
       for every request, so a fixed implementation sums both requests
       into one row, not two — and assert that row's counts are
       `2*turnInput`, `2*turnOutput`, `2*turnCacheRead`, `2*turnCacheWrite`.
       Against today's bug the post-reclaim write is silently fenced and
       never stored, so the row holds only one turn's counts
       (`turnInput`, `turnOutput`, …); the doubled counts are what
       distinguish the fix from the bug, not the row count, which is 1
       either way. The HTTP status the gateway returns is not part of the
       proof either, since a fenced ledger write doesn't affect the 200
       the upstream stand-in always sends.
   Proof: this test fails against the pre-fix code (gateway totals show
   one turn's counts, not two) and passes once step 1 lands.

## Risks

- **The new test is flaky on timing.** Reclaim depends on a real heartbeat
  tick noticing a forced lease expiry within the spec's `Eventually`
  window, same as the two existing reclaim specs in `run_test.go`, which
  already run at `TTL = 12s` / `Interval = 200ms` against a `30s` timeout
  without reported flakiness — reusing those exact values keeps this spec
  on already-trusted ground rather than inventing new timing.
- **`Do`'s two gateway requests race the reclaim.** The channel handshake
  (ready → expire/wait-for-new-lease → go) makes the ordering explicit
  rather than relying on sleeps; if the harness's `Do` goroutine and the
  main spec goroutine deadlock (e.g., the second channel is never closed
  because an assertion above it fails), Ginkgo's own per-spec timeout will
  surface it as a hang rather than a silent false pass — acceptable, since
  every other spec in this file that holds a turn has the same shape of
  risk and none have needed more than the default timeout.
- **This fix is narrowly scoped to the gateway's `Record` closure.** If
  another component in the codebase turns out to also capture
  `s.leaseID()` once instead of reading it live, this plan does not find
  or fix it — a grep during step 1's implementation
  (`grep -n leaseID internal/run/*.go`) already shows every other call site
  reads it inline at the write, so no sibling instance is expected, but the
  implementer should re-run that grep after editing to confirm nothing
  else changed shape.

## Decisions

- **Closure reads `state` live, rather than `reclaim` re-rotating the
  gateway step.** The work order names both as acceptable; the live-read
  option is smaller, matches the convention every other lease-consuming
  call site already follows, and does not reintroduce a second cache that
  itself could go stale on a repeat reclaim.
- **No change to `recordGatewayUsage`'s signature.** It already accepts the
  lease as a parameter; only the expression passed to it at the one call
  site changes.
- **Test lives in `gateway_test.go`, not a new file.** It needs both the
  gateway fixture (`gateway_test.go`) and the reclaim/expire helpers already
  shared in `support_test.go`; appending to the existing
  `Describe("The credential gateway in the run loop", ...)` block keeps it
  beside the other specs that already assert on `GetGatewayTotals()`.
- **No change to `mill status`/`mill cost` rendering code.** Confirmed by
  reading `internal/cli/read.go` that both commands query the store live;
  criterion 2 in the work order is satisfied once the write itself
  succeeds.
