# A scripted event can wait before it is emitted, so a fixture can be observed mid-step

## Approach

Give `fake.Script` two new, additive fields — `After map[int]time.Duration`
(a pre-send wait keyed by the index of the event it precedes in the output
slice) and `TerminalAfter time.Duration` — and make `fake.Harness.play`'s
existing send loop honor them with a cancelable wait before each send and
before the final `Finish`. `internal/harness/scripted` parses the new
`after:` YAML/JSON field into a `time.Duration` at `Load` time (refusing a
bad value the same way an unknown dispatch verb is refused) and threads it
through `Adapter.build`, remapping each event's original index to its
position in the output slice — `build` already shifts indices when it
inserts a synthetic `tool_result` for a dispatching `tool_call`, and the new
delay map has to track that same shift or a delay meant for one event would
land on the wrong one.

This is the "fake harness gains the same field" option the work order names,
chosen over the sibling option ("the adapter emits them one at a time")
because `fake.Script{...}` is constructed with a literal `Events
[]*harnessv1.Event` in 27 files outside this package (mostly
`internal/run/*_test.go`); changing `Events`'s shape breaks all of them,
while two new zero-value-safe fields break none. It is also chosen over
having `scripted` own the pause itself: `internal/harness/fake`'s own package
doc says the scripted adapter "never reimplements the turn/goroutine/terminal
machinery [fake] already has," and `fake.Harness.play` already owns
send/cancel/terminal sequencing (mutex, `cancelled` map, `stop` channel,
`Hold` select) — duplicating that inside `scripted` to interleave sleeps
would mean either calling `Start`/`Resume` more than once per real turn
(breaking the one-`Turn`-per-call contract every caller of `Turn.Wait`
relies on) or hand-rolling a second copy of `play`'s goroutine, with a second
place for its cancellation semantics to drift from the first. A bare
`time.Sleep` with no `ctx` was also considered and rejected outright: it
fails the cancellation acceptance scenario by construction.

`TerminalAfter` is scoped to the non-`Hold` branch of `play`; scripted turns
never set `Hold` (only `fake`'s own specs use it to test cancellation), so
the two features never need to interact, and giving `Hold` its own
`TerminalAfter` semantics is speculative scope this node does not ask for.

## Steps

1. **`fake.Script` gains `After` and `TerminalAfter`; `play` honors them.**
   `internal/harness/fake/fake.go`: add `After map[int]time.Duration` and
   `TerminalAfter time.Duration` to the `Script` struct, documented the same
   way `Do` and `Hold` are. In `play`'s goroutine, before
   `session.Events.Send(event)` for index `i`, if `script.After[i]` is set,
   wait on a `time.Timer` vs `ctx.Done()`; on `ctx.Done()`, call
   `turn.Finish(nil, ctx.Err())` and return without sending the remaining
   events. In the non-`Hold` branch, apply the same cancelable wait for
   `script.TerminalAfter` immediately before `turn.Finish(script.Terminal,
   nil)`.
   Proof: existing `internal/harness/fake` specs
   (`fake_test.go`, `fake_suite_test.go`) pass unmodified — the zero-value
   map/duration is a no-op, so this step changes no observable behaviour yet.
   Add one new spec here (or defer to step 3 if `scripted` is a thinner
   surface to assert through — decide when writing, see Decisions): a
   `Script` with `After: {0: 50*time.Millisecond}` on a two-event script
   delivers the first event no earlier than 50ms after `Start` returns, and
   a `Script` with `After: {0: 10*time.Minute}` whose `ctx` is cancelled
   mid-wait finishes with `context.Canceled` within ~1s (use
   `Eventually`/a deadline, never a fixed `time.Sleep` assertion longer than
   the wait itself).

2. **`scripted` decodes `after:` and refuses a bad value at `Load`.**
   `internal/harness/scripted/script.go`: add `After string` to `eventYAML`
   (`yaml:"after,omitempty" json:"after,omitempty"`) and to `terminalYAML`.
   In `eventYAML.toEvent`, parse `e.After` with `time.ParseDuration` when
   non-empty and return the parsed `time.Duration` as an added return value
   (or via a small struct wrapping event+delay — pick whichever keeps
   `toEvent`'s signature least awkward when writing it); a parse error is
   wrapped as `fmt.Errorf("after %q: not a valid duration", e.After)`,
   matching the existing `dispatch %q: not a verb this harness can call`
   style. `terminalYAML.toHarness`'s caller (`toTurn`) does the same for
   `t.Terminal.After` and stores it on a new `Turn.TerminalAfter
   time.Duration` field; `toTurn` stores each event's parsed delay in a new
   `Turn.Delays map[int]time.Duration`, keyed by the *original* event index
   (same index space `Turn.Dispatches` already uses, same loop).
   Proof: extend `internal/harness/scripted/script_test.go` — add an `after:`
   field to one event and the terminal in `testdata/turns.yaml`, assert
   `script[i].Delays` and `.TerminalAfter` decode correctly; add
   `testdata/bad-after.yaml` with `after: 5x` and assert `Load` refuses it
   with an error naming `after` (mirrors the existing
   `testdata/unknown-dispatch.yaml` / "refuses a dispatch verb outside the
   fixed list" spec).

3. **`Adapter.build` remaps indices and passes the delays through.**
   `internal/harness/scripted/adapter.go`: in `build`'s loop over
   `turn.Events`, after appending the original event, record its position in
   the output slice (`outIdx := len(events)-1`); if `turn.Delays[i]` is set,
   write it into a new `after := map[int]time.Duration{}` at `outIdx`. Pass
   `after` and `turn.TerminalAfter` into the returned `fake.Script`. The
   synthetic `tool_result` events `build` inserts for a dispatch never carry
   a delay (nothing in the YAML can address them), so no remapping is needed
   for those.
   Proof: this is the step the three specs the work order names line up
   with best — add them in `internal/harness/scripted/adapter_test.go`
   (or a new `after_test.go` beside it, whichever reads better once the
   other specs are in front of you):
   - an event with `after: 300ms` is emitted no earlier than 300ms after the
     one before it (assert via timestamps captured as `session.Events.Send`
     fires, using a `harness.Sink` that records `time.Now()` per call — the
     same shape `assertScriptedActivity` in `tests/acceptance/scripted_test.go`
     already uses to read event order back, but done here against the
     adapter directly rather than through a full run);
   - a scripted turn paused on `after: 10m` whose step context is cancelled
     ends the wait with the context's error within ~1s;
   - a script with no `after` anywhere behaves exactly as it does on `main`
     today (reuse an existing fixture like `testdata/session-a.yaml`
     unmodified and assert timing is not the bottleneck — e.g. the turn
     completes in well under a second).
   Also add a case where an event carries `after` *and* a dispatch precedes
   it in the same turn, to prove the index remap: extend
   `testdata/dispatch.yaml` (or add a sibling fixture) so the delay lands on
   the intended authored event, not the synthetic `tool_result` `build`
   inserts ahead of it.

4. **Document the field.**
   `docs/runbook.md`, in "## The scripted implementer" (the section that
   already documents `harness.scripted.script`, `docs/runbook.md:439-472`):
   add a paragraph naming `after` on an event and on a turn's `terminal`,
   its purpose (holding a step observably running long enough for a poller
   — a browser spec's `expect.poll`, `mill status`, `mill inspect` — to see
   it mid-step, not a general-purpose delay), and that the wait is charged
   against the step's own timeout since it runs inside the same context the
   step's harness call already carries.
   Proof: doc-only; reviewed by reading, not tested. Grep after writing to
   confirm no second "scripted harness" doc exists that also needs the note
   (`grep -rn scripted docs/` was already run in gather-context and found
   only `docs/runbook.md` and `docs/architecture.md`'s incidental mentions;
   confirm architecture.md needs no edit since it does not describe the
   scripted harness's own mechanics).

5. **Prove the live-run shape: `mill inspect`/`mill status` observe a paused
   step.** `tests/acceptance/testdata/workflows/scripted-feature/scripts/implement.yaml`:
   give the `implement` step's own turn (the fourth turn in the file, after
   gather-context/think/plan — confirm the exact turn by re-reading the file
   before editing, since the plan step also dispatches a write and the delay
   must sit on a real text/tool_call event, not the dispatch's synthetic
   result) a first event with `after: 5s`. `tests/acceptance/scripted_test.go`:
   extend the existing "A run costs no tokens" scenario (or add a new `It`
   beside it, whichever keeps the existing scenario's own timeout budget
   honest — `scriptedTimeout` may need widening by 5s+slack if reused) to
   assert, while the run is in that window: `mill status` (already exercised
   via `suite.service.Store` / the `inspect` helper this file defines) reports
   the run running at `implement`, and after the run finishes, `mill inspect`
   shows the `implement` attempt's duration at least 5s — computed the same
   way `assertScriptedActivity` already reads sealed activities back, or via
   the attempt's own start/finish timestamps if `InspectResponse` carries
   them (check `millv1.InspectResponse`'s step/attempt fields when writing
   this).
   Proof: `go test ./tests/acceptance/... -run TestAcceptance` (or however
   this suite is invoked — check `docs/runbook.md`'s own instructions for
   the acceptance tier's invocation before writing the command into CI/local
   docs) passes with the new assertion, and fails if the `after: 5s` line is
   reverted (spot-check by reverting locally and re-running before calling
   the step done).

## Risks

- **Index remapping in `build` is the trickiest single piece of this
  change** — get it wrong and a delay silently lands on a synthetic
  `tool_result` event or the wrong authored event, either inert or
  mis-timed. Mitigated by step 3's explicit dispatch+`after` fixture, which
  fails loudly (wrong event delayed) if the remap is wrong, rather than
  passing by accident.
- **`fake.Script`'s 27 external call sites** could in principle rely on
  `Script`'s set of fields via reflection or exhaustive struct-literal
  checks (e.g. a linter demanding every field named) — checked already via
  grep that they use `Events:`/`Terminal:`/etc. as named fields, so two new
  named fields are additive; if any site uses positional struct literals
  this breaks silently. Verified: none do (Go vet would already reject
  unkeyed struct literals here if any existed, and the ones spot-read all
  use keyed literals).
- **Choosing a wrong home for the new specs** (step 1 vs step 3) — not a
  functional risk, just a review-readability one; left as an explicit
  decision to make while writing, not a blocker.
- **Acceptance-tier timing flakiness**: a 5s `after` inside a 5-minute
  suite-wide timeout is generous, but CI hosts vary; if `scriptedTimeout`
  needs widening, do it explicitly and say why in the diff rather than
  silently inflating it.
- **mill#75 (socket resolver fix) still unmerged**: this plan depends on
  nothing from it and touches none of the files it would touch: the
  environmental live-tier failures the supervisor named are out of scope
  and must be left as-is; if the tier fails only on those after this
  change, that is expected, not a defect in this work.
- **`docs/harness.md` does not exist**: the work order names it
  conditionally ("or wherever documented"); confirmed in gather-context that
  `docs/runbook.md` is the actual home, so step 4 targets that file, not a
  new one — creating a new `docs/harness.md` would duplicate documentation
  rather than extend it.

## Decisions

- **Additive fields on `fake.Script`/`fake.Harness`, not adapter-owned
  timing.** Work order offered both; chosen for the reasons in *Approach*.
- **Per-event delay keyed by index (`map[int]time.Duration`)**, mirroring
  `Turn.Dispatches`'s existing pattern, rather than a parallel slice or a
  richer per-event struct — smallest change consistent with an established
  precedent in the same file.
- **`TerminalAfter` scoped to the non-`Hold` branch of `fake.Harness.play`.**
  Scripted turns never set `Hold`; no acceptance criterion exercises the
  combination, so it is left undefined/unapplied there rather than
  speculatively designed.
- **Doc target is `docs/runbook.md`'s "The scripted implementer" section**,
  not a new `docs/harness.md`, per the grep already run in gather-context.
- **Acceptance-tier live-run proof (step 5) is in scope for this node**,
  not deferred to steading, since the work order's own acceptance criteria
  list the `mill inspect`/`mill status` behaviour as this node's checkbox
  (steading's fixtures, named separately in Deliverables, are steading#15
  and steading#10's own plans consuming this once merged — a different,
  later thing).
- **Error message for a bad `after` value**: `after %q: not a valid
  duration`, chosen to name the field per the acceptance criterion's
  wording ("refused at load with a message naming the field, like an
  unknown dispatch verb is") and to match `dispatchVerbs`' existing phrasing
  style exactly.
