# A scripted harness reachable from mill serve, for a run that costs no tokens

## Approach

Add a new harness adapter, `internal/harness/scripted`, that is a thin
loader/router in front of the harness the repository already has:
`internal/harness/fake`. `fake.Harness` already does everything a scripted
turn needs — replay a fixed list of events, end on a terminal, run an
arbitrary `Do` hook against the real session before it does — the only
things missing are (1) a file format a workflow author can write turns in,
(2) per-session-name turn tracking (today's `fake.Harness` has one counter
shared by every session that holds it), and (3) a way for a turn to reach
the real workspace socket so `plan` and `commit` produce evidence the
verifier can check against the actual checkout. `scripted.Adapter` supplies
exactly those three things and nothing else; it builds one `fake.Script` per
call and hands it straight to a freshly constructed `fake.New(script)`, so
the goroutine/Turn/Finish machinery is never duplicated.

Two other findings shape the scope:

- Of `scripted-feature`'s skill steps, only `plan` (evidence: artifact, a
  real file the mill reads back) and `commit` (evidence: commit, the mill
  reads the branch head itself) need a script that dispatches a real verb.
  `gather-context`/`think`/`simplify`/`review-plan`/`review` need no
  dispatch at all, and `implement` needs one real `fs.write` only to leave
  a genuine change in the tree for `commit` to commit.
- `pr` and `merge` are dropped from `scripted-feature` rather than mirrored:
  `pr`'s `url` evidence is produced by the run loop's own call to
  `s.repo.Forge.OpenPR(...)` (`internal/run/execute.go:pullRequest`)
  against a real forge, and `forges()` registers only gitlab and github —
  there is no bare-repository forge to point it at, and
  `docs/runbook.md`'s "Without a forge" section and the acceptance suite's
  own `feature-no-forge` derivation (`tests/acceptance/workflows_test.go`)
  already establish the pattern of dropping exactly these two steps rather
  than inventing one (see Decisions).
- Every place the codebase already gates a workflow feature behind
  `$MILL_ACCEPTANCE` does it at two layers: the CLI seam that would let a
  run skip real work (`internal/cli/run.go:checkSkillOverrides`) and,
  because harness registration also happens per-run, the run's harness
  registry (`internal/cli/run.go:harnessesFor`). This node adds a third
  gate the other precedent didn't need: workflow *load* time
  (`internal/workflow/definition.go`, beside the existing
  `retiredHarnessName` check), because acceptance criterion 3 requires
  `mill workflow push` itself to refuse `scripted-feature` without the
  variable, before any run exists.

The baseline considered and rejected: teach `fake.Harness` itself to read a
file and dispatch verbs. That is a second, incompatible calling convention
bolted onto the harness the node says not to duplicate, and it would still
need the per-session cursor and gate work below — no smaller than wrapping
it, and it mixes "spec-constructed fixture" with "file-driven, workflow
-reachable adapter" in one type.

## Steps

1. **Script format.** New file `internal/harness/scripted/script.go`
   defining the on-disk turn format and its decode into `fake.Script` -
   shaped values: a `Script` is a list of `Turn`s; a `Turn` is an ordered
   list of `Event`s (`text`, `tool_call`, `tool_result`, `usage`,
   `heartbeat`, each with the fields `fake`'s constructors already take —
   `fake.Text`, `fake.ToolCall`, `fake.Heartbeat`, `fake.UsageEvent`) plus a
   `terminal` (`final_message`, `structured_output`, `exit`, matching
   `fake.Terminal`/`fake.NeverRan`). A `tool_call` may additionally name a
   `dispatch` verb (e.g. `git.commit`) and its request arguments; when
   present, the paired `tool_result` is *not* written in the file — it is
   produced at run time from the real response (step 3). Decoding accepts
   JSON or YAML (the file extension picks the codec, matching how
   `internal/workflow` already decodes `workflow.yaml`).
   **Files:** `internal/harness/scripted/script.go`,
   `internal/harness/scripted/script_test.go`.
   **Test:** a ginkgo spec decoding fixture files
   (`testdata/turns.yaml`, `testdata/turns.json`) covering all five event
   kinds, a terminal, and a `dispatch` tool call, asserting the decoded
   `Turn`s carry the right `*harnessv1.Event`s and that an unknown event
   kind or a `dispatch` verb outside the fixed verb list is refused with a
   named error — `go test ./internal/harness/scripted/...`.

2. **Adapter, no dispatch yet.** New file
   `internal/harness/scripted/adapter.go`: `type Adapter struct` holding
   the workflow directory and a mutex-guarded `map[string]*cursor` keyed by
   `session.ID` (`cursor` = parsed `[]Turn` for that session's script file,
   cached by resolved path, plus a `next int`). `Adapter.Start`/`.Resume`
   resolve the script path from `session.Options["script"]` (required;
   refuse with a named error if absent or if it is not a
   `harness.scripted` options document at all — mirrors how the real claude
   adapter reads its own options), load and cache it on first use, take
   `turns[next]` (clamping to the last turn once a session runs past its
   script, matching `fake.Harness`'s own tolerance for extra calls),
   advance the cursor, build one `fake.Script{Events, Terminal}` from it,
   and return `fake.New(script).Start(ctx, session, prompt, attachments)`
   (or `.Resume`, forwarding whichever verb was called — a fresh
   single-script `fake.Harness` answers either the same way).
   `Adapter.Cancel` is a no-op: no turn in this node's scripts ever holds,
   so nothing is ever running for `Cancel` to reach (recorded under Risks).
   `var Name = "scripted"` exported alongside, mirroring `fake.Name`.
   **Files:** `internal/harness/scripted/adapter.go`,
   `internal/harness/scripted/adapter_test.go`.
   **Test:** a ginkgo spec giving two sessions (`implement`, `review`)
   distinct script files and driving one Start plus several Resumes on
   each, asserting: events replay in the file's order on the sink,
   terminals match, and — the point of the per-session cursor — resuming
   `review` never advances `implement`'s position and vice versa.
   `go test ./internal/harness/scripted/...`.

3. **Real verb dispatch.** Extend the adapter: when building a turn's
   `fake.Script`, a `dispatch` tool call becomes a `Do` closure (capturing
   `prompt` and `session`, both in scope at the `Start`/`Resume` call site)
   that dials `socket.Dial(session.Workspace.Socket, session.Workspace.Token)`
   and calls the named verb for real, then mutates the pre-built
   `tool_result` event's content/`is_error` in place before `fake.Harness`
   sends it — the same pointer is in the `Events` slice `Do` runs against,
   so the mutation is visible to the send loop that follows it (this is
   why `Do` running *before* the events are sent, exactly as `fake.Script`
   already documents it, is load-bearing here). One request field gets
   runtime substitution: `plan`'s `fs.write` path is not known until the
   mill renders it per run, but it is always the mill's own prompt telling
   the session where to write (`internal/run/artifact.go:artifactBrief`,
   the literal `` Write it to `%s` in the checkout `` line) — the adapter
   extracts that path with one fixed regex against `prompt.Text` and
   substitutes it for the literal placeholder `${artifact_path}` in a
   dispatched call's arguments. No other verb in this node's scripts needs
   a runtime-known argument: `commit`'s `git.commit` call omits `Paths`
   entirely (stages everything currently in the tree) rather than needing
   to know `plan`'s exact filename.
   **Files:** `internal/harness/scripted/adapter.go` (extended),
   `internal/harness/scripted/dispatch_test.go`.
   **Test:** spin a real `internal/workspace/socket` server (the package's
   own test helper, backed by `internal/workspace/local` against a temp
   git checkout — the same construction `internal/run`'s own tests already
   use) and drive a turn with a `dispatch: fs.write` tool call through the
   adapter, asserting the file actually lands in the checkout at the path
   extracted from a real `artifactBrief`-shaped prompt string, and a second
   turn with `dispatch: git.commit`, asserting `git log` on the checkout
   shows the real commit. `go test ./internal/harness/scripted/...`.

4. **Registration and the two `MILL_ACCEPTANCE` gates.**
   - `internal/workflow/definition.go`: add
     `scriptedHarnessName = "scripted"` beside `harnessName`/
     `retiredHarnessName`, and in the per-step harness loop in `toProto()`,
     refuse a step naming `harness.scripted` when
     `os.Getenv("MILL_ACCEPTANCE") == ""`, naming the step and the variable
     in the error — this is what makes `mill workflow push` refuse
     `scripted-feature` (acceptance criterion 3). It runs at `Load`, so
     `mill run`/`mill work` refuse the same way before a run is ever
     created.
   - `internal/cli/run.go:harnessesFor`: register
     `scripted.Name → scripted.NewAdapter(opts.workflowDir)` in the
     registry only when `os.Getenv(acceptanceEnv) != ""` (reusing the
     existing `acceptanceEnv` constant) — this is what makes the harness
     reachable at all from `mill run`/`mill work`/`mill serve`, all three
     of which already share this one registry constructor.
   **Files:** `internal/workflow/definition.go`,
   `internal/workflow/definition_test.go`, `internal/cli/run.go`,
   `internal/cli/run_test.go`.
   **Test:** a workflow-level test pushing a fixture workflow whose one
   step has `harness.scripted`, asserting `workflow.Load` fails naming
   `MILL_ACCEPTANCE` without the env set and succeeds with it
   (`go test ./internal/workflow/...`); a cli-level test asserting
   `harnessesFor` returns a registry whose `Names()` includes `"scripted"`
   only when the env is set (`go test ./internal/cli/...`).

- Passing looks like: all of the above exit 0, and the criterion-5 diff

## Risks

- **`Cancel` is a no-op.** If a future scripted scenario needs a held turn
  cancelled mid-run, this adapter cannot express it — `fake.Harness`
  itself supports `Hold`/cancellation, but because `scripted.Adapter`
  builds a fresh `fake.Harness` per call, there is no long-lived instance
  for `Cancel` to reach. None of this node's acceptance criteria need a
  cancel, so it is out of scope here; if it is needed later, the adapter
  would need to keep the last-constructed `fake.Harness` reachable by
  session ID between calls, which is a small addition, not a redesign.
- **The `${artifact_path}` extraction is a single regex against one fixed
  mill-authored string** (`artifactBrief`'s `` Write it to `%s` in the
  checkout ``). If that string changes, the adapter's extraction breaks
  silently rather than at compile time. Mitigated by step 3's dispatch
  test asserting the extraction against the real `artifactBrief` output
  (not a copied literal), so a future change to that format fails this
  package's own test, not just the acceptance run.
- **Step 3's test infrastructure is the plan's one open dependency**
  (noted under Files as uncertain): if no existing helper wires
  `workspace/socket` + `workspace/local` + a temp checkout together outside
  `internal/run`'s suite, step 3 adds one. This is the plan's own problem
  to solve, not a blocker on anything else — it does not change any other
  step's shape, only adds a small test-support file.
- **`clean-tree` failing on purpose (step 5) depends on `commit`'s first
  attempt staging a strict subset of the tree's changes.** If a later
  change to `workflows/feature` alters what `commit`'s skill or `clean-tree`
  actually check, `scripted-feature`'s script does not update itself (it is
  a fixed YAML file, not derived from the real skill). This is inherent to
  mirroring a workflow as data rather than code; the acceptance run (step
  7) is exactly the test that would catch the drift, since it asserts the
  criterion-2 ledger shape directly.
- **Two full acceptance-suite runs in one test (criterion 5) roughly
  doubles step 7's wall time.** Acceptable: the whole point of this node is
  a harness that costs no tokens and no network call, so the run itself is
  fast; nothing here waits on a model.

## Decisions

- **Gate location:** `internal/workflow/definition.go`'s existing per-step
  harness-name loop, beside `retiredHarnessName` — the only existing
  precedent for a restricted harness name, and it already runs inside
  `Load`, which is what `mill workflow push` calls, satisfying acceptance
  criterion 3 without a second load path.
- **Registration location:** `internal/cli/run.go:harnessesFor`, the one
  registry constructor already shared by `mill run`, `mill work`, and
  `mill serve` — no new wiring needed for `mill serve` specifically.
- **Script granularity:** one file per session name (per the node's own
  wording), not per step — matches how a session already spans several
  steps and keeps the turn ordering visible in one place per session
  rather than scattered across per-step files.
- **Reuse over reimplementation:** `scripted.Adapter` never reimplements
  turn/goroutine/Finish machinery; every call constructs a `fake.Script`
  and delegates to a fresh `fake.New(script)`. This is the smallest way to
  honor "do not write a second fake" literally — the second package is a
  loader and a dispatcher, not a second implementation of the interface's
  event-replay behavior.
- **`fake` package itself is left unmodified.** No `ToolResult` helper is
  added to `fake.go`; `scripted.Adapter` builds the one
  `*harnessv1.Event_ToolResult` it needs (for the dispatch case) directly,
  since it is the only package that needs it and adding a public helper to
  `fake` for one caller is not justified.
- **`pr` and `merge` are dropped, not mirrored**, despite the node's note
  that scripts should go through real verbs "against a local bare
  repository as the runbook's 'Without a forge' describes": there is no
  bare-repository forge in this codebase (`forges()` registers only gitlab
  and github), and `docs/runbook.md`'s "Without a forge" section describes
  a run that *parks at* `pr` on a host with none configured, not one that
  opens a real PR against a bare repo. The smallest change that still
  reaches `done` is the one the acceptance suite already uses for the same
  problem: derive `scripted-feature` the way
  `tests/acceptance/workflows_test.go` derives `feature-no-forge`, dropping
  exactly `pr` (`url` evidence) and `merge` (`status` evidence), the two
  steps whose evidence only a forge can state. `commit`'s real
  `git.commit` dispatch remains the node's one genuine-verb proof point.
- **Skill content is copied verbatim, not rewritten**, from
  `workflows/feature`/`workflows/quick-fix` — `Load` requires the files to
  exist and hashes them into the workflow version, but nothing in this
  workflow ever has a model read them, so writing new prose for them would
  be effort spent on text nothing reads.
