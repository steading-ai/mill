# The breaker parks a run whose findings exceed skift's comment and body limits

## Approach

Bound the two writes `park` makes *before* either is sent, and make `park`
survive a write being refused anyway.

For sizing: a low-level primitive trims one blob of text to a byte budget,
keeping its tail (the useful summary in a Ginkgo/`go test` report is last)
and, when it cuts, appending one line naming the bytes dropped, the artifact
that holds the whole thing, and the `mill logs` command that shows it. On top
of that, a fair-split step divides the comment's budget across however many
rounds there are — smaller rounds keep their whole text, and what they don't
use is handed to the rounds still over budget — so a single oversized round
cannot starve the others, and in particular the last (most recent, most
relevant) round is never the one reduced to nothing. The gate body reuses the
already comment-sized findings text (which is always small enough to fit
inside the larger body budget) and gives the span story whatever room is
left, trimming it with the same low-level primitive only when it doesn't fit
— no fair split needed there since findings has priority and span story is
supporting context, not the thing that caused the park.

For resilience: every round is attached to the node as its own artifact
first, independent of whether the comment built from it needs any trimming,
so `mill logs`/the artifact is always there to point to. The comment write
is then attempted once with the bounded text; if it still comes back
refused, that is logged and replaced with a one-line comment naming the
refusal, reusing the same request id (the failed call stored nothing, so the
key is free to replay under). A fenced write is the one exception — it is
returned unchanged, because a stale lease means the run is being abandoned
by the rest of the loop already, and writing a substitute comment or filing
a gate under it would be meaningless. Filing the gate, recording the park,
and releasing the lease all happen regardless of whether either comment
landed: the gate is what asks the human, and nothing about a comment
succeeding or not may gate that.

**Rejected:**

- *Catch `resource_exhausted` and retry trimmed.* Ruled out directly by the
  acceptance criteria (`git grep resource_exhausted internal/run/` must stay
  empty) and it is also the shape of bug being fixed: reacting to a specific
  refusal after the fact is exactly what turned one presentation error into
  an infinite loop.
- *Trim the whole assembled comment as one blob, tail first.* Cheapest to
  write, but trimming the tail of oldest-first concatenated rounds cuts the
  **newest**, most relevant round first — backwards from what the work order
  asks for and from what a human reading the gate needs.
- *Fixed equal-share truncation per round, no redistribution.* Satisfies
  "trim the tail" but not "the last round is never wholly cut": with uneven
  round sizes, an equal split can still zero out a later round while an
  earlier, smaller round's unused share goes to waste.
- *Fairly split the body budget between findings and span story the same
  way rounds are split.* Not what the work order describes ("the body fits
  ... with the span story included, the span story trimmed the same way
  *when it must be*") — findings caused the park and keeps priority; span
  story is supporting context and only gives up room if there isn't enough
  left.
- *Take skift's limits from the vendored source or a `go mod download` of
  the pinned module, as the work order first suggests.* Neither exists on
  disk here: `vendor/github.com/steading-ai/skift` carries only the
  generated `gen/skift/v1` packages actually imported (skift's `internal/domain`
  is not importable and was never vendored), and there is no populated
  module cache entry for skift's full source either.
- *Compare mill's constants against a skift checkout's current working
  tree* (`internal/domain/limits.go` as checked out right now, the same
  checkout `internal/testsupport/skift.go` points `skift serve` at for the
  integration fixtures). Rejected on review: the one checkout available on
  this machine's own test hosts tracks skift's `main`, which has already
  moved past the commit mill's go.mod pins (skift#6 raised
  `MaxCommentBytes` to 256 KiB on 2026-09-26, three days after the commit
  mill depends on) — so comparing against the working tree would fail the
  spec by construction on exactly the hosts where it can run, and give no
  protection anywhere else. The drift spec instead resolves the exact
  commit mill's go.mod pins (`go list -m -f '{{.Version}}'`, the trailing
  hex of the pseudo-version) and reads `internal/domain/limits.go` **at
  that commit** out of the checkout's own git history (`git show
  <hash>:internal/domain/limits.go`) — verified against the checkout this
  machine actually has: the pinned commit's object is present even though
  the working tree is three commits ahead, and its constants
  (`MaxBodyBytes = 256 << 10`, `MaxCommentBytes = 64 << 10`) match what
  mill mirrors. It skips, rather than fails, when no checkout is found, the
  checkout has no `.git` (e.g. a plain export), or the pinned commit isn't
  reachable in its history (e.g. a shallow clone) — matching how the rest
  of the suite already treats a missing skift checkout.

## Steps

1. **Mirror skift's ceilings and catch drift against the pinned commit, not
   whatever a checkout's working tree happens to have checked out.**
   - `internal/testsupport/skift.go`: export the existing checkout lookup
     (`skiftRepo`) as `SkiftRepo() string`, so both the integration fixture
     and the new drift spec share one place that knows where a skift
     checkout lives, rather than two copies of the same `MILL_SKIFT_REPO`
     fallback logic.
   - `internal/run/breaker.go`: add `maxCommentBytes = 64 << 10` and
     `maxBodyBytes = 256 << 10`, each commented as mirroring skift's
     `internal/domain.MaxCommentBytes` / `MaxBodyBytes` **at the commit
     mill's go.mod pins** (not importable from here, and not necessarily
     what any given checkout's working tree currently has).
   - `internal/run/limits_test.go` (new): a spec that calls
     `testsupport.SkiftRepo()` and skips if empty; otherwise runs `go list
     -m -f '{{.Version}}' github.com/steading-ai/skift` (a local read of
     the build list already resolved in `go.mod`/`go.sum` — no network),
     parses the trailing 12-hex-character commit out of the pseudo-version,
     and runs `git -C <checkout> show <hash>:internal/domain/limits.go`
     against the checkout's git history — not its working tree — to read
     `MaxCommentBytes`/`MaxBodyBytes` exactly as they stood at the commit
     mill actually depends on. Skips, naming why, if the checkout has no
     `.git`, the pinned commit isn't reachable in it (e.g. a shallow
     clone), or the version string can't be parsed as a pseudo-version;
     otherwise asserts the two parsed values equal mill's mirrored
     constants.
   - **Test:** `go test ./internal/run/ -run TestRun` (the Ginkgo suite
     entrypoint) picks the new spec up. Verified against this machine's own
     skift checkout (`/mnt/lima-stead-data/skift/checkout`, `main` at
     commit `b725036`, three commits ahead of the one mill's go.mod pins):
     `git show 460425ce6443:internal/domain/limits.go` resolves cleanly
     even though the working tree is ahead, and its `MaxBodyBytes`/
     `MaxCommentBytes` match mill's two constants — so the spec passes
     here, rather than failing by construction the way a working-tree
     comparison would. It skips, naming why, on a host with no skift
     checkout at all, and fails loudly if mill's constants and the pinned
     commit's disagree. No other behavior changes in this step — `go build
     ./...` still succeeds and the existing breaker specs are untouched.

2. **Bound the comment and the body, and attach every round as an
   artifact.** All in `internal/run/breaker.go`:
   - A low-level primitive, `trimTail(text string, budget int) (shown
     string, dropped int)`: returns `text, 0` unchanged if it already fits;
     otherwise keeps the tail within `budget` minus room for the cut-marker
     line it will carry, and reports how many bytes were dropped.
   - A fair-split helper, `splitBudget(sizes []int, budget int) []int`:
     water-filling allocation — sizes already under their equal share keep
     their whole allowance, and the remainder is redistributed to the
     others, iterating until stable — so nothing over budget-with-enough-
     total-room is starved to zero ahead of a smaller neighbor.
   - `park` attaches each round in `rounds` as its own artifact before
     building any text, named `<run>-<step>-round-<i>` (1-indexed) via
     `s.skift.AttachText`, request id
     `skift.RequestID(run, step+fmt.Sprintf("-findings-round-%d", i), attempt)`.
     This happens unconditionally — cut or not — so the citation in a cut
     marker is always valid and `mill logs` always has the full record
     regardless of what got trimmed.
   - `roundsOf` becomes budget-aware: it takes the rounds, the per-round
     artifact names, and `maxCommentBytes` minus the fixed wrapper text's
     own size; splits that budget with `splitBudget` over the rounds'
     sizes; trims each round with `trimTail`; and for any round that was
     cut, appends the line naming the bytes dropped, the round's artifact
     name, and `mill logs <ref> --step <step> --attempt <n>` (the attempt
     number a round pointer names is inferred from `sr.GetAttempt()` counted
     back by the round's distance from the last one — see *Decisions*).
   - `parkBody` reuses `roundsOf`'s already comment-sized output for the
     findings portion (guaranteed ≤ `maxCommentBytes` ≤ `maxBodyBytes`), and
     gives `spanStory` whatever of `maxBodyBytes` is left after the fixed
     wrapper text and findings; if that isn't enough, `spanStory`'s output is
     passed through `trimTail` once as a single blob before being embedded.
   - **Test:** extend `internal/run/breaker_test.go`'s "A step that keeps
     failing" describe block with a new spec — four rounds of 60 KB each —
     asserting: the node's comments (`f.comments`) has one comment under
     65536 bytes ending with a line naming bytes dropped and `mill logs`;
     the run parks with a gate whose body is under 262144 bytes; and the
     node's artifacts carry exactly one per round (four), each holding that
     round's full, untrimmed text. Also add small non-DB-labeled specs
     (fast, no real skift needed) directly exercising `splitBudget` and
     `trimTail` on a few shapes — already-fits, one huge round among small
     ones, a round exactly at budget — to pin the redistribution behavior
     the integration spec alone would not distinguish from a simpler bug.
     `go test ./internal/run/` passes, including the untouched "Escalation
     has a price" spec (its rounds are small enough that nothing is cut,
     proving the new code path is a no-op in the common case).

3. **Make a refused comment survive.** `internal/run/breaker.go`, in
   `park`: wrap the existing `s.skift.Comment` call — on error, if
   `errors.Is(err, skift.ErrFenced)`, return it unchanged (today's
   behavior: abandon, let the rest of the loop's fencing path handle it);
   otherwise log the refusal and call `s.skift.Comment` again, same request
   id, with a one-line body naming the refusal (e.g. "the findings comment
   was refused: `<err>`; see the artifacts attached to this node"). Whether
   that replay itself succeeds or not, `park` proceeds to file the gate,
   record the park, and release the lease exactly as it does today — none
   of that is conditioned on the comment.
   - **Test:** a new spec in `internal/run/breaker_test.go`, built on the
     existing `failingPatches` fake transport (`support_test.go`) matched
     against `add_comment` ops, so the findings comment is refused
     regardless of size. Assert: the run still parks, the gate is still
     filed, `Store.Park` is still recorded, the lease is still released
     with reason `budget`, and the node's one comment is the one-line
     refusal notice rather than the findings. `go test ./internal/run/`
     passes with this spec added; `git grep -n "resource_exhausted"
     internal/run/` stays empty because nothing here matches on that
     string — the fake failure is injected by the test transport, and the
     production code path only branches on `errors.Is(err, skift.ErrFenced)`.

4. **Document it.** `docs/architecture.md`, the circuit breaker bullet
   (currently line 281): add one clause that the findings are trimmed to
   skift's comment and body ceilings, and that each round's full text lives
   as an artifact on the node, `mill logs` being how to read it back.
   **Test:** none beyond a read-through; this is prose, not behavior.

5. **Whole-suite pass and acceptance-criteria check.** No new files.
   Run the full proof list below and confirm every acceptance criterion
   this workspace can check. The guest-deployment criterion (live run,
   `mill status`, `journalctl`) cannot be exercised from a checkout and is

## Risks

- **The guest-only acceptance criterion can't be proven from this
  checkout.** The unit and integration specs prove the sizes are bounded
  and the park survives a refusal; they don't prove the *deployed* mill
  binary, talking to the *deployed* skift, behaves the same way under real
  load. Mitigation: call this out explicitly rather than claim it's
  covered; whoever deploys this change should watch one park through to
  gate-filed on the guest before considering mill#72's incident closed.
- **Mill's pinned skift dependency (64 KiB comment ceiling) is already
  behind skift's own `main` (256 KiB, skift#6, merged 2026-09-26).** This is
  why the drift spec compares against the *pinned commit* via git history
  rather than a checkout's working tree (see *Approach*, rejected options):
  the one checkout available on this machine's test hosts already tracks
  `main`, ahead of mill's pin, so a working-tree comparison would fail
  there by construction. If mill's go.mod is bumped past skift#6's raise
  without updating `maxCommentBytes` alongside it, the mirrored constant
  becomes *conservative* (trims more than strictly necessary) rather than
  unsafe — so a missed bump degrades gracefully — and the drift spec
  catches the mismatch outright the next time it runs, since it always
  resolves whatever commit go.mod pins at that moment. The residual gap is
  only a host with no skift checkout, or a shallow one missing the pinned
  commit's object, where the spec skips rather than checks — the same
  offline limitation "or from the pinned module" ran into (see *Approach*,
  rejected options).
- **The round → attempt-number mapping in a cut marker's `mill logs
  --attempt N` can be wrong when an attempt was aborted or upstream-refused
  without producing findings** (`attemptsAt`'s own comment in `run.go`
  describes exactly this gap: retries are counted net of aborted/refused
  attempts, but `s.findings` has no attempt numbers recorded per round).
  The mapping used here (count back from the parking attempt) is a
  best-effort pointer for a human, not something anything asserts
  byte-for-byte; if it's wrong the artifact and the comment's own round
  numbering are still correct, only the suggested CLI flag might miss. Not
  worth solving further without a work order asking for exact attempt
  bookkeeping per round.
- **`splitBudget`'s redistribution could, in principle, need more than one
  pass to converge (a round freed by giving away its unused share might
  still be over what's newly available to it).** Bounded and small — at
  most as many passes as there are rounds, and rounds are few (bounded by
  a step's `retries`) — so this is a correctness detail for the
  implementation and its unit specs to pin, not a design risk.

## Decisions

- Kept the low-level trim/split helpers inside `internal/run/breaker.go`
  rather than a new file: the work order names `breaker.go` as where this
  logic goes, and it has no callers or reason to exist outside `park`,
  `roundsOf`, and `parkBody`.
- Put the drift spec in its own `internal/run/limits_test.go` rather than
  folding it into `breaker_test.go`: it needs a skift *checkout* on disk,
  not a running skift *service* — conflating it with the DB-labeled,
  real-server-backed breaker specs would tie an unrelated, cheap
  file-read check to the suite's most expensive fixture.
- Exported `testsupport.SkiftRepo()` rather than duplicating the
  `MILL_SKIFT_REPO`/default-path lookup in the new spec — one lookup, two
  callers.
- Findings get priority over the span story when both compete for the
  body's budget (span story is trimmed only when there isn't room left
  after findings), rather than a fair split between the two the way rounds
  are split against each other — the work order's own phrasing ("the span
  story trimmed the same way *when it must be*") reads as a fallback, not
  a symmetric allocation, and findings is what caused the park.
- The round → attempt number cited in a cut marker is inferred by counting
  back from the parking attempt (`sr.GetAttempt() - (len(rounds)-1-i)`)
  rather than tracked explicitly per round, since `s.findings` carries no
  attempt numbers today and adding that bookkeeping is out of scope for
  what this node asks for (see *Risks*).
- A refused replay comment reuses the *same* request id as the original,
  per the work order's own note that the failed call stored nothing so the
  key is free — not a new, second request id.
- The drift spec reads skift's constants at the commit mill's go.mod pins,
  via `git show <hash>:internal/domain/limits.go` against a checkout's git
  history, rather than reading whatever that checkout's working tree
  currently has checked out. A working-tree comparison was the first
  design and was rejected on review: the only skift checkout this
  machine's own test hosts have already tracks skift's `main`, ahead of
  mill's pin, so it would fail the spec by construction on the hosts where
  it can run at all, while giving no drift protection anywhere else.
