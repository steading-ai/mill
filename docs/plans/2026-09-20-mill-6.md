# A run that ends badly leaves its node ready, and the worker reclaims it at once

## Approach

The circuit breaker already gives every *ordinary* step failure a way to
stop the node being reclaimed: once a step's retries and `on_failure` are
spent, `park` (`internal/run/breaker.go`) fails the run into `parked` and
files a gate that blocks the node in skift, so `ClaimNext` never returns it
again until a person answers. That path is correct and untouched by this
plan; `internal/run/revise.go` shows every step-walk failure eventually
reaches it.

The workflow-selection path (`internal/run/select.go`) is deliberately
outside the breaker — its own comment says the assessment step's "retries
are spent here rather than by the circuit breaker" — but when selection's
retries or its config checks are exhausted, it returns a bare `error` with
nothing else. That error unwinds through `drive` to `Runner.stop`
(`internal/run/run.go`), which releases the lease with reason `crash` and
nothing more: no terminal run status, no mark on the node. The node is open
and unheld, so the next `ClaimNext` (the same worker, a second later, or a
different worker or host) claims it straight back into the identical
failure. That is exactly the incident: the assessment step exhausted its
three retries against a refused credential, and reclaimed forever at a full
step-timeout each time.

`internal/run/run.go`'s existing `lostSandbox` (openWorkspace finding the
run's machine gone) already does the right thing for a different failure:
`Store.Fail` the run, then `Skift.Hold` the node while the lease is still
live — sidestepping `skift hold`'s refusal to touch a leased node, which is the
exact obstacle the incident's person hit by hand. `openRun` already refuses
to resume a `failed` run, naming `mill restart`/`mill rerun`. The store's
transition table already allows `selecting → failed`. Nothing new needs
inventing: this plan extracts `lostSandbox`'s Fail-then-Hold pairing into a
small shared helper and applies it to every place in `select.go` that
returns a **locally-constructed, content- or config-driven error** —
one that retrying the identical run will reproduce exactly, the same
property `failSelection`'s own comment already claims ("there is nothing
... whose retries could be spent on trying again") without ever having
acted on it.

Left deliberately alone: `Runner.stop`'s generic catch-all branch, and every
error inside `select.go` that is bubbled from a `call(...)` RPC (a
transient store/skift blip). `run_test.go`'s "Resuming after a crash" and
"Skift first, store second..." specs pin exactly this: a process that dies
or a single failed RPC mid-run must stay `running` and resumable by a later
claim, not be turned into a permanent failure. Making *every* `stop()`
error terminal — the more sweeping reading of the work order — would pass
this node's own acceptance criteria but silently break that already-tested
resilience, trading one bug for a regression a reviewer would have to
rediscover. This plan holds the node only where the same run failing again
would prove nothing new.

**Rejected: a comment + label the worker's claim filter skips.** Would need
a new skift label convention, a change to every `ClaimNext` caller's label
set, and a new way for `skift node show` to explain "why" (today that reads a
`Hold`, not a label) — more surface for the same outcome `Hold` already
gives for free, including the "why" acceptance criterion.

**Rejected: a ledger-recorded back-off honoured by the claim loop.** The
incident's own resolution — stopping `mill.service`, holding by hand,
restarting it — shows the back-off has to survive a service restart and be
visible to any worker on any host, not just this process's memory. Anything
that persists cross-process and cross-host converges back to writing
something skift can see, which is what `Hold` already is; a bespoke ledger
field would duplicate it.

**Rejected: making `Runner.stop`'s whole catch-all terminal.** Covered
above — it would make transient store/skift RPC failures permanent,
contradicting `run_test.go`'s existing crash-recovery specs.

## Steps

1. **Add the shared `failRun` helper, and have `lostSandbox` use it.**
   In `internal/run/run.go`, extract a function
   `func (r *Runner) failRun(ctx context.Context, s *state, requestKey string, cause error) error`
   that does exactly what `lostSandbox` does today: `Store.Fail` the run
   with `cause.Error()` as the reason (while `s.lease` is still valid), then
   `Skift.Hold` the node under the same lease and reason (logging rather
   than failing if the hold write itself errors, as `lostSandbox` does
   today), and return `cause` unchanged so `stop`'s existing generic branch
   still releases the lease afterward exactly as it does now. Rewrite
   `lostSandbox` to call it instead of repeating the two calls inline.
   **Proof:** `internal/run/reconcile_test.go`'s existing "A live run with no
   machine fails as a lost sandbox" spec passes unmodified — this step is a
   pure extraction, no behavior change for the one caller that exists today.

2. **Route the assessment's retry-exhaustion through `failRun` — the
   incident's own trigger.** In `internal/run/select.go`'s `assess`, the
   branch at `sr.GetAttempt() > int64(step.GetRetries())` currently returns
   `false, fmt.Errorf("run %s: the assessment did not close after %d
   attempts: %w", ...)`. Change it to build that same error and return
   `false, r.failRun(ctx, s, skift.RequestID(s.run.GetId(), "assess-exhausted", sr.GetAttempt()), err)`.
   The step run itself is already failed a few lines above this branch
   (existing `Store.FailStepRun` call); this only adds the run-level
   terminal state.
   **Proof:** extend the existing "treats an empty signals list as
   malformed" spec in `internal/run/select_test.go` (it already drives
   exactly this branch — three malformed attempts, retries spent) with new
   assertions: `f.runOf(ctx).GetStatus()` is `RUN_STATUS_FAILED`, and
   `f.client.Node(ctx, f.nodeRef)`'s `GetHold().GetReason()` contains "the
   assessment did not close" — mirroring the pattern
   `internal/run/reconcile_test.go` already uses for `lostSandbox`.

3. **Route `failSelection`'s two callers through `failRun`.**
   `internal/run/select.go`'s `failSelection` already documents that "the
   run stops here": add a `failRun` call after its existing
   `Store.FailStepRun`, using `skift.RequestID(s.run.GetId(), "select-failed", sr.GetAttempt())`
   as the key. Its two callers — a malformed tier
   (`selectAssessed`, tierOf error) and a workflow the assessment named that
   is not in scope — need no change themselves.
   **Proof:** extend the existing "An assessment cannot invent a workflow"
   spec in `select_test.go` with the same two new assertions as step 2
   (run `FAILED`, node held, reason naming the out-of-scope workflow).

4. **Route the two remaining local dead ends in the selection path.**
   `internal/run/select.go`: `selectDefault`'s `"no workflow named %q"` (a
   project pinned to a workflow that does not exist) and
   `assessmentDefinition`'s `"%s has no project default and no workflow
   named %q to assess with"` and `"workflow %s has no step %q"` (the
   `build-workflow` definition missing or malformed) each become
   `return r.failRun(ctx, s, skift.RequestID(s.run.GetId(), "select-failed", s.run.GetGeneration()), fmt.Errorf(...))`
   in place of `return fmt.Errorf(...)`. No step run exists yet at either
   call site, so the generation — not an attempt number — is what varies
   the key per run; a constant key would collide the moment a second run
   ever hits this branch (skift refuses a repeated `request_id` whose
   content differs, per `proto/skift/v1/service.proto:23-25`), the `Hold`
   write would fail, and the node would be left unheld — exactly the
   reclaim loop this node exists to close. All three are static-
   configuration problems: an identical retry reproduces them exactly, same
   as steps 2–3.
   **Proof:** one new spec in `select_test.go`, "A project default naming no
   workflow fails the run and holds the node" — `f.runner(withDefault("no-such-workflow"))`
   (or the fixture's equivalent of pinning a missing default), asserting the
   same run-`FAILED`/node-held shape. `assessmentDefinition`'s two branches
   are covered by the same `failRun` call proven in steps 2–4's specs and
   are not independently re-tested end-to-end (see Decisions) — they would
   need a fixture with no `build-workflow` pushed at all, a materially
   bigger setup for the same already-proven code path.

5. **`docs/domain-model.md` §Run.** Add to the `failed` state's bullet
   (currently: gate denied, or the node closed underneath the run) a third
   cause — selection ending in a config or content problem it cannot retry
   its way out of — and note that this case additionally holds the node in
   skift, the same way the existing `lostSandbox` case already does,
   naming both in one place so the state diagram's prose matches what the
   code now does uniformly.
   **Proof:** read against the code from steps 1–4; no executable check, but
   `docs/domain-model.md` is named as a deliverable so the review reads it
   against `failRun`'s call sites.

6. **`docs/runbook.md` §"When it fails".** Add a bullet: a run that fails
   this way leaves the node held, with the reason on the node (`skift node
   show`); a person clears the hold with skift's own tooling before
   `mill restart` (fresh generation) or `mill rerun --from <step>` (retry
   the same run) can be claimed again — `mill restart`/`mill rerun` alone
   do not lift a hold, since holding and a node's open/closed status are
   independent (`internal/skift/project.go`'s `Hold` comment; `Restart`'s
   own status check in `internal/run/restart.go` does not touch holds).
   **Proof:** same as step 5 — a documentation deliverable, checked by
   reading it against the behavior steps 1–4 implement, not a test.

7. **Whole-tree gate.** `make lint && make test`.

## Proof

```
make lint             # go vet, golangci-lint
make test-unit        # non-DB specs; confirms the package still builds and the pure-refactor step (1) is inert
make test-db          # select_test.go and reconcile_test.go's DB-labelled specs, including the new/extended ones
make test             # everything, the gate AGENTS.md names before finishing
```

Passing looks like: `make lint && make test` clean, and each acceptance
criterion traceable to a spec —

- AC1 ("the same worker does not claim that node again without a person's
  act") — steps 2–4's specs proving the run reaches `RUN_STATUS_FAILED`,
  which `openRun` (`internal/run/run.go`) already refuses to resume, and the
  node carries a `Hold`, which keeps `ClaimNext` from ever returning it.
- AC2 ("`skift node show` ... says why") — the same specs' assertion on
  `node.GetHold().GetReason()`, which is exactly the field skift's own
  `node show` reads (proven already by `reconcile_test.go`'s existing lost-
  sandbox spec on the same field).

## Risks

- **`failRun`'s `Store.Fail` call races a concurrent heartbeat or another
  write under the same lease.** Not a new risk — `lostSandbox` already
  makes this exact call today under the same lease-fencing rules every
  other store write in the run loop uses; nothing about moving it to a
  shared helper changes the fencing.
- **A `select.go` branch this plan missed still returns a bare, deterministic
  error.** `assessmentDefinition`'s `workflowInScope` call and
  `requireHarnessesOf` are left as bubbled/ambiguous rather than converted
  (see Decisions) — if `requireHarnessesOf`'s failure turns out to be as
  deterministic as the others, it would reclaim-loop the same way. Flagged
  rather than guessed at: converting it needs reading what that check
  actually guards against, which this plan did not do, to avoid holding a
  node over what might be a legitimately transient environment check.
- **Extending two existing specs changes their pass/fail shape.** If a
  reviewer wants the incident's exact scenario as its own named spec rather
  than folded into "treats an empty signals list as malformed," that is a
  one-line follow-up (split the assertions into a new `It`), not a redesign.
- **`docs/runbook.md`'s "clear the hold" instruction names no exact `skift`
  command.** This checkout has no vendored copy of skift's own CLI
  reference to confirm the literal verb (`skift unhold`, `skift node unhold`, or
  similar); the doc will describe the action ("skift's own tooling clears
  a hold") rather than assert a flag name that cannot be verified from here.
  Fix accompanying a later pass once skift's CLI reference is reachable, or
  the implementer confirms it live against a running skift instance.

## Decisions

- **Only `select.go`'s locally-constructed, content/config-driven errors
  are converted; RPC-bubbled errors and `Runner.stop`'s generic branch are
  left resumable.** The work order is written generally ("a run that
  fails"), but the two existing crash-recovery specs in `run_test.go` are
  the concrete evidence that "every failure is terminal" is the wrong
  reading — this plan takes the narrower one that fixes the demonstrated
  defect (selection has no do-over, unlike the step walk) without
  regressing tested resilience.
- **The shared mechanism is `Store.Fail` + `Skift.Hold`** (the "hold"
  option among the work order's three), reusing `lostSandbox`'s existing,
  tested pattern rather than a new label or ledger field — smallest change
  that satisfies both acceptance criteria, per the Approach section.
- **`assessmentDefinition`'s `requireHarnessesOf` and `workflowInScope`
  calls are left unconverted**, on the discriminator "a local `fmt.Errorf`
  describing a static config problem" vs. "a value bubbled from a `call(...)`
  RPC or an unread check" — see Risks. Noted rather than silently dropped.
- **No dedicated end-to-end spec for `assessmentDefinition`'s two branches**
  (missing `build-workflow`, missing `assess` step) — they share the exact
  `failRun` call already proven by steps 2–4's specs; a fixture with no
  `build-workflow` pushed is a materially different setup for no new
  signal about the mechanism itself.
- **No new mill-side "unhold" command.** `lostSandbox` set this precedent
  already (nothing in this codebase unholds a node it holds); clearing a
  hold stays skift's own CLI surface, named in the runbook without a new
  code path.
