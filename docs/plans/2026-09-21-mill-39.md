# A worker that cannot open a claimed node re-claims it at once, without backoff

## Approach

Two mechanisms, applied together, because the work order's central sentence is an
*or*: "no release path may return to `ClaimNext` without either a wait or a reason
the same node cannot come back."

1. **Extend the existing Hold pattern** (`internal/dagger/project.go:88-99`,
   already used by `lostSandbox` and `noRepository`/`failRun`,
   `internal/run/run.go:796-856`) to the refusal paths that don't use it yet but are
   the same shape: deterministic given the worker's own state, and wrong for every
   worker, not just this one. Two are already in the code and untested for this:
   `openRun`'s two `ErrRefused` branches (run.go:688-699 — a node still open with a
   `DONE` or `FAILED` run underneath it, the "wrong kind" of AC2). A third is named
   by AC2 directly and matches the pattern exactly: `requireHarnesses`
   (`internal/run/walk.go:25-45`) refuses a workflow step whose harness this worker
   has no adapter for — "unmet precondition," provably the same answer on the next
   claim until the binary or the workflow changes.
2. **A worker-local backoff, as the general safety net**, for every other
   pre-step refusal — `openRun`'s own read failing, `repository()`'s non-`vcs_url`
   errors, `openWorkspace`'s non-lost-sandbox errors, `selectWorkflow`,
   `restoreRetried`, `resumePark` — categories that may be transient (a forge outage,
   a dropped connection) and so do not deserve a permanent, person-must-act Hold, but
   still must not spin. This is also the backstop for the two failure-based Hold
   sites above: `failRun`'s own comment says the Hold write "is logged rather than
   failed on," so a Hold that does not land must not leave the node to spin either.

Rejected: relying on Hold alone for everything (approach 2 of the gather-context
note). It would require deciding, for every current and future pre-step failure,
whether it is "deterministic enough" to hold — a classification call the work
order does not ask for and that a new failure mode would silently get wrong by
omission. The work order's own wording ("no release path... without *either*")
treats the wait as the default and Hold as the stronges­t case, not the only one.

Rejected: reordering `drive()` to resolve the repository before `openRun`'s
`CreateRun`/`SetLease` write, so a doomed-from-the-start claim never touches the
run ledger at all. `docs/ledger.md`'s "Resume" algorithm (the authoritative
design, per `AGENTS.md`) is explicit that `CreateRun`/`SetLease` is the first
thing Resume does, before workspace or workflow — reordering it would contradict
a documented invariant, not fix a bug. AC3's "one `set_lease` per real takeover"
is satisfied instead by the backoff/Hold work above: once a node cannot be
re-claimed within its wait or is Held, there is no second cycle to write a
second `set_lease` for. Its stronger sentence, "a claim the worker abandons
before running a step writes nothing to the run," is satisfied for every claim
*after* the first by the same mechanism (the worker short-circuits before ever
calling `ExecuteClaimed` again); it does not apply to the first, documented
`CreateRun` write, which the design requires. This is a real tension between the
Scenario's wording and `docs/ledger.md`; noted under **Risks** rather than
resolved by working around the documented algorithm.

## Steps

1. **Give the worker a signal for "refused before any step ran."**
   `internal/run/run.go`: add a sentinel, `ErrCouldNotOpen`, and wrap every
   `drive()` return that happens before `r.walk(...)` is called — the direct
   `return r.stop(ctx, s, err)` after `openRun`, the two `repository()` branches
   (`noRepository` and the generic one), `openWorkspace`, `selectWorkflow`,
   `requireHarnesses`, `restoreRetried`, `resumePark` — with
   `fmt.Errorf("%w: %w", ErrCouldNotOpen, err)` (Go 1.20 multi-`%w`). Leave the
   final `return r.stop(ctx, s, r.walk(...))` unwrapped: a run that ran at least
   one step and then failed is not this bug, and must not be throttled like it is.
   **Test**: a table-style addition to `internal/run/run_test.go` (or wherever
   `drive`/`ExecuteClaimed` is already exercised end to end) asserting
   `errors.Is(err, run.ErrCouldNotOpen)` is true for a forced pre-open failure
   (e.g. a generic, non-`NoVCSURLError` error from `Repositories`) and false for a
   failure `Harnesses`/a fake step returns from inside a real `walk()` after the
   run has progressed past selection.

2. **Hold the two `ErrRefused` branches in `openRun`, and `requireHarnesses`'s
   refusal.** `internal/run/run.go:688-699`: before returning `ErrRefused` for a
   done-or-failed-but-open node, call `s.dagger.Hold(ctx, dagger.RequestID(...),
   s.lease, s.node.GetReference(), reason)`, mirroring `failRun`'s call
   (run.go:851) and its "logged, not failed, if the write itself fails" stance.
   `internal/run/walk.go:25-45` (or its caller in `drive()`, whichever already
   holds `s`): the same, with a reason naming the missing harness and step, the
   same information already in the returned error's text.
   **Test**: extend `internal/run/reconcile_test.go`'s existing
   `MatchError(run.ErrRefused)` spec (line 204) — or add a sibling spec next to
   it — to also assert, the way `internal/run/repository_test.go:75-79` already
   does for `noRepository`, that the node's `GetHold().GetReason()` is set and
   the node stays `STATUS_OPEN` but is not reclaimed on a second `ClaimNext`.
   Add one new spec in `internal/run/walk_test.go` (create if it does not exist
   as a Ginkgo file, following the fixture in `worker_support_test.go`) for
   `requireHarnesses`: a workflow naming a harness the fixture's runner has no
   adapter for, asserting the node is Held with a reason mentioning the harness
   and step name, matching the message `requireHarnessesOf` already builds.

3. **A worker-local backoff for every remaining pre-step refusal.**
   `internal/run/worker.go`: replace `loggedNoRepo` — which only ever suppressed
   a log line, never the reclaim, for a category that no longer needs either
   since it Holds — with a small tracker (a mutex-guarded
   `map[string]*nodeBackoff{until time.Time; attempt int}`, keyed by node id) that:
   - is consulted in `claim()` right after `ClaimNext` returns and before the
     node is handed to `w.drive`: if the node is still within its window, the
     worker releases the lease immediately (`Release(CRASH, "worker: <reason>,
     backing off")`, no call into `Runner` at all — so nothing is written to the
     mill store for this cycle, satisfying AC3's "writes nothing to the run" for
     every cycle after the first), gives the slot back, and sleeps the
     *remaining* window (respecting `w.stopping`/`ctx.Done()`) before looping;
   - is updated in `w.drive` (worker.go:321-341): on `err == nil`, clear the
     node's entry (a real takeover happened); on `errors.Is(err,
     run.ErrCouldNotOpen)` (from step 1) — including the already-Held cases from
     step 2, as the backstop for a Hold write that itself failed — start or
     extend the node's window (double the previous wait, capped) and log once,
     at the moment the window is opened or extended past its previous log,
     never on every consult.
   Base wait and cap are new constants (`internal/run/worker.go`, beside
   `DefaultWait`): proposed `1s` doubling, capped at `5m` — see **Decisions**.
   **Test**: a new `Describe` in `internal/run/worker_test.go`, next to "A
   project with no repository" (line 289), forcing a generic, non-Hold pre-open
   failure (e.g. `o.Workspaces` returning a plain error, not
   `workspace.ErrLostSandbox`) on a single node, and asserting over a short
   window (using the fixture's already-`quick` TTL/interval) that: the number of
   times the forced failure is invoked stays small and does not grow linearly
   with wall-clock time (i.e., successive attempts are spaced further apart, not
   claimed back-to-back); the `warnCounter` (already used at worker_test.go:294)
   shows exactly one line for the node's refusal streak, not one per attempt;
   and the node's run row (`f.runOf`) shows the lease's `worker_ref` set once,
   not once per attempt (the direct proof for AC3's first clause — "one
   `set_lease` per real takeover").

4. **Prove the node's own Scenario with an executable spec, not a log check.**
   The Scenario ("given a project whose repository the worker refuses... the
   worker claims each once, releases it with the reason, and does not claim it
   again within the TTL; dagger's lease table gains one row per node, not
   thousands") is not the same claim as Step 2's `ErrRefused`/`requireHarnesses`
   specs (different refusal category) or Step 3's generic-backoff spec (not
   Held, reclaimed on a growing schedule rather than never within the TTL); it
   needs its own proof. Extend `internal/run/worker_test.go`'s existing "A
   project with no repository" spec (line 289) — or add a sibling `It` beside
   it in the same `Describe` — with a per-node attempt counter: wrap
   `o.Repositories` (the fixture's forced `NoVCSURLError`) to increment a
   `map[nodeID]int` (or two `atomic.Int64`s, one per fixture node, the same
   shape as `repository_test.go`'s `resolved atomic.Int64` but kept per node
   this time) each time it is called for that node. After the existing
   `Eventually` confirms both nodes are Held, add a `Consistently` held for
   longer than the fixture's TTL (`quick`'s `3*interval`) asserting each
   node's counter is exactly `1`: one claim, no reclaim within the TTL — the
   literal Then clause. Since each counted call corresponds to one
   `ClaimNext`/lease taken, "counter stays at 1 per node" is the direct proof
   of "dagger's lease table gains one row per node, not thousands" without
   reading dagger's storage directly.

5. **Docs.** `docs/sandbox.md` §Reconciliation (or a new short section beside
   it): one paragraph naming the two mechanisms together — Hold for a refusal
   every worker would repeat, a growing local wait for everything else — so the
   rule this node states in prose ("no release path may return to `ClaimNext`
   without either a wait or a reason") has a documented home, the way
   Reconciliation already documents `lostSandbox`/`noRepository`. No test; proven
   by review, per `AGENTS.md`'s "design is frontloaded and authoritative."

## Proof

- `make lint` — must pass unchanged; no new lint categories are introduced.
- `make test` (or the package-scoped `go test ./internal/run/...` if the
  Makefile target is slower than needed while iterating) — every existing spec
  must keep passing, in particular the two that already pin current behaviour:
  `internal/run/repository_test.go`'s no-repository spec and
  `internal/run/worker_test.go`'s "A project with no repository" spec, since
  the backoff tracker replaces the field (`loggedNoRepo`) those specs exercise
  indirectly through the shared warning path.
  All new specs from Steps 1-4 pass.
- The node's own Scenario is proven by Step 4's extended spec, not a manual
  check: passing means each of the two no-repository nodes' per-node call
  counter is exactly `1`, held through a `Consistently` window longer than the
  fixture's TTL — one claim, one Hold, no reclaim within the TTL, which is the
  Scenario's Then clause and the AC's "not thousands" in one assertion.

## Risks

- **`docs/ledger.md`'s "Resume" algorithm and AC3's strongest sentence pull in
  different directions** for the very first claim on a node that turns out to
  be doomed (see *Approach*, rejected reordering). If a reviewer reads AC3 as
  requiring zero ledger writes even on the first attempt, this plan does not
  satisfy it as written — it satisfies "one `set_lease` per real takeover" and
  "nothing written on every claim after the first," not "nothing written ever."
  If that reading is intended, the fix is the rejected reorder plus rewriting
  `noRepository`/the two `openRun` Hold sites to Fail nothing and Hold only,
  which is a design change to `docs/ledger.md` itself, not a quick fix — flag
  back rather than silently take the larger change.
- **The `requireHarnesses` Hold assumes the failure is caused by the worker's
  own configuration (missing adapter) or the workflow's, both deterministic
  from the claim alone.** If a later change makes harness availability
  per-run (e.g. dynamic negotiation), Holding on it would wrongly make the
  refusal permanent. Not true today (`walk.go:17-24`'s own comment: "the check
  is at run start... the answer is known there"), so this is safe now; worth a
  one-line comment at the call site saying why, so a future change to harness
  resolution notices the coupling.
- **Backoff constants (`1s` doubling, capped `5m`) are a guess**, not derived
  from a documented number. If review wants them tied to the lease TTL (AC2's
  literal "for the lease TTL" phrasing) rather than a fixed cap, `Worker` would
  need the configured TTL exposed from `dagger.Client` (today `options.ttl` is
  unexported, no accessor) — a small additional change, called out here so it
  is not a surprise mid-implementation.
- **Existing `worker_test.go` "A project with no repository" spec asserts
  exactly one warning "as long as the second node's failure is the same
  project already warned about"** — replacing `loggedNoRepo`'s per-project
  dedup with a per-node backoff tracker must preserve this project-level
  message dedup (two different nodes, same broken project, one line), not
  regress it to one line per node. The new tracker's log-once rule is
  per-node-streak; the existing spec's guarantee is per-project. Both must
  hold, which likely means keeping the project-level warning dedup for the
  `NoVCSURLError` message as it is today, additive to (not replacing) the new
  per-node backoff bookkeeping — worth confirming against the spec before
  removing `loggedNoRepo` outright, rather than assuming they are the same
  mechanism.

## Decisions

- **Backoff base and cap**: `1s` doubling per consecutive refusal of the same
  node, capped at `5m`. The work order permits either "remembers... for the
  lease TTL" or "dagger is told"; deterministic categories get the latter
  (Hold, Step 2), so the worker-local backoff (Step 3) only needs to be a
  bounded safety net for non-deterministic failures, not to match the TTL
  exactly.
- **Release reason on a backoff-short-circuited claim**: `RELEASE_REASON_CRASH`
  with a descriptive detail string. The vendored `dagger.v1` contract
  (`proto/dagger/v1`) has no reason built for "worker backing off"; `CRASH` is
  already the reason generic, non-graceful releases use elsewhere in this file,
  and adding an enum value is a contract change out of scope here.
- **`loggedNoRepo`'s fate**: kept as a distinct project-level dedup for the
  `NoVCSURLError` message (see Risks), not folded into the new per-node
  tracker, unless implementation shows the two can share one structure without
  weakening either spec's guarantee.
- **Scope of Hold additions**: limited to the two `openRun` `ErrRefused`
  branches and `requireHarnesses`, the three categories AC2 names by example
  ("no repository" already done by mill#20, "wrong kind," "unmet precondition").
  `selectWorkflow`/`restoreRetried`/`resumePark`/generic `repository()` /generic
  `openWorkspace()` errors are left to the general backoff (Step 3) rather than
  individually classified, per the *Approach* section's rejection of
  case-by-case Hold classification.
