# The record's retention is a policy, and doctor says what a host holds

## Approach

Add a `retention` policy, resolved per project with a deployment-wide
default, and a periodic sweep that enforces it over the sealed frames and
twins under `--log-dir`. The sweep never touches the `activity` index table
— the work order's "never touches the index" is read literally — so both
`twin_days` (delete the twin file) and `compact_days` (rewrite the frame)
are filesystem-only operations. Compaction's hard constraint is that four
`RenderActivity` cases (`Prompt`, `HarnessStderr`, `CheckOutput`, `Check`)
print their body in full, not through `summarize()`, so no existing body
kind can hold a compacted attempt's rendered text without either
re-truncating it on render (the `Text` case re-applies `summarize()`) or
mislabelling it (`HarnessStderr`'s render prefix). The frame is instead
rewritten to hold exactly one new-kind record, `Activity_Compacted{
Compacted{ text } }`, whose `text` is what `mill logs` actually prints for
the attempt, rendered once before the rewrite. That is *not* the same
string `RenderedLog`/`ActivityRenderer.Render` alone produce: `mill logs`'s
own client-side renderer, `logsRenderer` (`internal/cli/logs.go:420-447`),
adds the `-- <step> attempt N started --` / `-- <step> attempt N ended:
<reason> --` marker lines around `attempt_started`/`attempt_ended` records,
which `RenderActivity` renders as `""` (it only covers what happened inside
the session). Reusing `RenderedLog` as originally drafted would silently
drop those two lines from a compacted attempt. `logsRenderer` itself cannot
be called from `internal/run` (it lives in `internal/cli`, which already
imports `internal/run`, not the reverse), and its `AttemptEnded` marker
needs a `(step_run_id) -> (step, attempt)` lookup built from a whole run's
`StepRunDetail` list — machinery this node has no reason to pull in. But a
sealed attempt's own frame is self-contained (one `step_run_id`, seq-ordered,
so its `attempt_started` record — carrying `step`/`attempt` directly —
always precedes its `attempt_ended` record within the same file), so
`internal/run/retention.go` gets its own small, local renderer,
`renderCompacted`, that reproduces `logsRenderer`'s two marker cases from
that in-frame state alone and defers to `ActivityRenderer.Render` for
everything else — matching `mill logs`'s actual output without touching or
sharing code with the existing, tested `logsRenderer`/`RenderedLog`
(intentional small duplication over a cross-package refactor of working
code; see Decisions). `RenderActivity` still gains one new, non-summarizing
case for `Activity_Compacted` itself, so a compacted frame's one record
renders back through the ordinary path (`ActivityRenderer.Render`'s
existing `default: RenderActivity(a)` arm needs no change, since the new
kind is not `Text`/`Thinking` and never participates in delta accumulation).
The frame rewrite reuses `writeFrame`/`verifyFrame` (`internal/run/seal.go`)
unchanged, called with a one-record slice; its returned
`[]*ActivityIndexRow` is discarded rather than inserted, which is what
keeps the index row count and every column on it exactly as sealed
(confirmed against `internal/server/logs.go`'s `readIndexedActivities`/
`readRunActivities`: they already read whatever a frame actually decodes to
and do not require it to match the index's row count, so a frame reduced to
one record needs no change there).

Ages and project names come from the store, not the filesystem: `SealAttempt`
does not touch file mtimes, and `step_runs.ended_at`/`runs.ended_at`
(`internal/store/migrations/00005_step_runs.sql`, `00004_runs.sql`) already
exist, so no migration is needed. The sweep enumerates candidate files from
disk under `<log-dir>/<runID>/`, distinguishing a frame from a twin by
suffix: `FramePath` is `ActivityPath` (`<step>.<attempt>.activity`) plus
`.zst`, i.e. `<step>.<attempt>.activity.zst`; `TwinPath` is
`<step>.<attempt>.twin.tar.zst` — both end in `.zst`, so the match is on
`.activity.zst` for a frame and `.twin.tar.zst` for a twin, in that order,
never a bare `.zst` suffix (which a twin also satisfies). It groups files
by the `runID` directory they live under, and resolves each distinct run's project and every attempt's
`ended_at` with one `Inspect` RPC per run directory (`StoreService.Inspect`,
`proto/mill/v1/store.proto`): its `InspectResponse.steps` is a
`[]StepRunDetail`, each carrying `step_run.step_name`, `step_run.attempt`
and `step_run.ended_at` for every attempt of that run, and its
`summary.run.node_ref` gives the project the same way the ledger sweep and
`internal/run/run.go:664` already read it — `strings.Cut(nodeRef, "#")`,
no dedicated helper exists or is needed. An attempt whose `ended_at` is
unset (still open) or whose run `Inspect` no longer finds (already gone
from the store) is left alone; the sweep only acts on what it can positively
age.

The policy config mirrors the existing `cache-global-cap`/`cache-global-caps`
pair (`internal/cli/config.go`) exactly: one scalar `retention` (the
deployment default) plus one `map[string]string` `retention-projects`
(keyed by project name, overriding the default for that project), both
flat strings in the same small grammar — `keep`, or a comma-separated
`twin_days=N`/`compact_days=N` pair — parsed by a single `ParsePolicy`
function, the same shape `parseGlobalCaps` already establishes for a
per-name override map of otherwise-scalar-shaped config. This was chosen
over a nested YAML mapping (`retention: {default: ..., projects: {...}}`)
because no existing key in `Config` is nested, and the flat pair keeps
`configKeys`/`docs/tools.md`'s generated table entries one line each, like
every other key.

The sweep runs from `internal/run/retention.go` as a method on `*Runner`,
`SweepRetention`, called from the same two places `internal/run/worker.go`
already calls the ledger's `Sweep` from — `start()` before the first claim,
and the `sweepDue`-gated call inside the claim loop — reusing the existing
`SweepInterval`/`lastSweep` cadence rather than adding a second timer, per
the work order's "on worker start and on the sweep interval" (singular).
When the deployment's resolved policy is `keep` everywhere (the zero value,
and the default), the sweep logs one line and returns without walking the
filesystem, satisfying "the default policy removes nothing, and the sweep
says so in one log line" cheaply on every host that never touches the
setting.

`mill doctor` gains a fourteenth probe, `activity`, placed after `space` in
both `ProbeNames` and `runProbes` (another host-local disk fact, the same
family). It is a local filesystem read only — no `WorkerService` RPC
delegation, matching `probeSpace`/`probeWorkflows`, both of which already
assume `doctor` runs where the log directory actually is — walking
`--log-dir` (a flag new to `doctor`, defaulted via the same `defaultLogDir()`
`run`/`work` already use) to report frame and twin counts, total bytes, the
oldest frame's age, and the resolved policy in force for `--project`.

**Rejected: shrink each oversized-body record in place at compaction time,
mirroring `applyCeiling`'s per-kind truncation.** `applyCeiling` only ever
runs against the four kinds `RenderActivity` renders in full (it does not
touch `Prompt`/`HarnessStderr`/`Check*` at all today), so this would need
new shrinking logic for exactly the bodies "renders the same lines as
before" most needs untouched — and every other kind (`ToolCall`, `Usage`,
`Heartbeat`, …) would still need to survive intact for `RenderActivity` to
reproduce its line, which means most of the frame's bytes are kept anyway.
It does not get to "the frame's only content is the summary" at all.

**Rejected: store the rendered text in the existing `Text` body.**
`RenderActivity`'s `Text` case is `fmt.Sprintf("%s text %s\n", stamp,
summarize(body.Text.GetText()))` — it re-applies `summarize()`'s 240-byte
cap on render, so a longer already-rendered string would be silently
re-truncated on every future read, corrupting exactly the content
compaction exists to preserve losslessly.

**Rejected: resolve attempt age from file mtime instead of the store.**
Avoids one `Inspect` call per run directory, but `SealAttempt` never sets
frame mtime to anything but "when sealed" today, and a compaction rewrite
(`writeFrame` to a `.tmp` then rename) resets it again — mtime-based aging
would need `os.Chtimes` bookkeeping on every rewrite to stay correct, for a
value the store already has for free via a column that exists today.

## Steps

1. **Add the `Compacted` proto case and its render.**
   - `proto/mill/v1/mill.proto`: add `message Compacted { string text = 1; }`
     (doc: "The rendered summary lines a compacted frame's frame keeps in
     place of the bodies retention dropped — exactly what `RenderedLog`
     produced for this attempt before compaction, docs/activity.md
     §Lifecycle 'Retention'."), and `Compacted compacted = 27;` as the next
     `Activity.body` oneof case (last existing is `attempt_ended = 26`).
     Additive: a new oneof case, no existing field renumbered or removed.
   - Regenerate: `make generate` (buf generate, both templates).
   - `internal/run/activity.go`: in `RenderActivity` (`internal/run/activity.go:614`),
     add `case *millv1.Activity_Compacted: return body.Compacted.GetText()`
     — no stamp prefix, since the stored text already carries each
     original line's own timestamp.
   - **Test**: `internal/run/activity_test.go`, a case asserting
     `RenderActivity` on an `Activity_Compacted` record returns its `text`
     field verbatim, byte for byte, including embedded newlines and existing
     timestamps. `go test ./internal/run/...` (this package) passes.

2. **`internal/run/retention.go`: policy type, parsing, and frame compaction.**
   - New file. `type Policy struct { TwinDays, CompactDays int }` (zero
     value is `keep`); `func ParsePolicy(s string) (Policy, error)` accepts
     `"keep"` (or `""`) and `"twin_days=N"`, `"compact_days=N"`, or both
     comma-separated, erroring on an unknown key or a non-positive N,
     following `cache.ParseSize`'s error-shape precedent used by
     `parseGlobalCaps`.
   - `func renderCompacted(activities []*millv1.Activity) string`: one
     `NewActivityRenderer()` plus local `step`/`attempt` state, reproducing
     `logsRenderer.render`'s two marker cases
     (`internal/cli/logs.go:430-436`) from the frame's own
     `attempt_started`/`attempt_ended` records and delegating everything
     else to `ActivityRenderer.Render` — see Approach for why this is a
     small, deliberate duplication rather than a shared call into
     `internal/cli`.
   - `func compactFrame(path, stepRunID string) (bool, error)`: `ReadFrame`
     the path; if it already decodes to exactly one record whose body is
     `*millv1.Activity_Compacted`, return `false, nil` (idempotent no-op —
     the sweep runs repeatedly and must not re-render an already-compacted
     frame). Otherwise call `renderCompacted` on the decoded slice, build a
     single `*millv1.Activity{Seq: 1, Source:
     millv1.ActivitySource_ACTIVITY_SOURCE_MILL, At: <last record's At>,
     Truncated: true, Bytes: int64(len(text)), Body:
     &millv1.Activity_Compacted{Compacted: &millv1.Compacted{Text: text}}}`,
     and call `writeFrame(path, stepRunID, []*millv1.Activity{rec})`
     followed by `verifyFrame` — both reused from `internal/run/seal.go`
     unchanged — discarding `writeFrame`'s returned index rows without
     inserting them. Returns `true, nil` on an actual rewrite.
   - **Test**: `internal/run/retention_test.go`. `ParsePolicy` table test
     (`"keep"`, `"twin_days=7"`, `"compact_days=30"`,
     `"twin_days=7,compact_days=30"`, and rejected inputs). `renderCompacted`
     against a fixture with `attempt_started`, a `Prompt`, a `Text`, and
     `attempt_ended` records, asserted equal to what a hand-built
     `logsRenderer`-equivalent (or, more directly, a real `mill logs`
     invocation over the same records through the existing
     `internal/cli/logs_test.go` harness — see step 6's cli-tier addition)
     produces for the identical input, so the two marker implementations
     are pinned against each other, not just internally consistent.
     `compactFrame` against a frame `writeFrame` built from that same
     fixture: asserts `ReadFrame` after returns exactly one record with
     `Truncated` true whose `Compacted.Text` equals the pre-compaction
     `renderCompacted` output, and that calling `compactFrame` a second
     time returns `false, nil` and leaves the file byte-identical
     (idempotency). `go test ./internal/run/...` passes.

3. **The sweep: enumerate, age, act, log — plus its `Options`/config plumbing.**
   - `internal/run/run.go`: add to `Options` — `Retention Policy` (deployment
     default, docs one-liner pointing at docs/activity.md §Lifecycle
     "Retention") and `RetentionProjects map[string]Policy`.
   - `internal/run/retention.go`: `func (r *Runner) policyFor(project string) Policy`
     (map lookup, falling back to `r.options.Retention`); `func (r *Runner)
     SweepRetention(ctx context.Context) (RetentionReport, error)` — a small
     `RetentionReport{TwinsRemoved, FramesCompacted int}` returned for the
     caller to log, mirroring `machine.Report`'s shape but scoped to this
     concern rather than reusing it (this is not a ledger-reconciliation
     finding). If `r.options.Retention` is the zero value and
     `RetentionProjects` is empty, log one line ("retention: keep (default);
     nothing to sweep") and return immediately. Otherwise: `filepath.WalkDir`
     under `r.options.LogDir`, one level of `runID` subdirectories, collecting
     names by suffix — `.activity.zst` for a frame, `.twin.tar.zst` for a
     twin, checked in that order since a twin also ends in `.zst` (skip
     `.tmp`, `writeFrame`/`writeTwin`'s own in-flight suffix); group by
     `runID`; for each, call `Inspect` once,
     skip the run entirely on a not-found error (nothing to age it against);
     resolve project from `strings.Cut(summary.GetRun().GetNodeRef(), "#")`
     and the run's policy via `policyFor`; for each attempt found on disk,
     match it to a `StepRunDetail` by `(step_name, attempt)`, skip if
     `ended_at` is unset; compute `age := now.Sub(ended_at)`; if
     `policy.TwinDays > 0 && age >= twinDays`, `os.Remove` the twin path,
     ignoring `os.ErrNotExist` (already gone — a prior sweep, or an attempt
     with no session); if `policy.CompactDays > 0 && age >= compactDays`,
     call `compactFrame`. Accumulate the report, log one summary line
     naming the log directory and both counts, return.
   - `internal/run/worker.go`: call `w.options.Runner.SweepRetention(ctx)`
     immediately beside the existing `w.options.Runner.Sweep(ctx, ...)` call
     in `start()` (~line 247), and again inside the `sweepDue`-gated block
     in the claim loop (~line 336) — same trigger points, same interval,
     a distinct call because it is a distinct report and a distinct log
     line, not folded into the ledger sweep's own `machine.Report`. This is
     a two-line, uncontroversial addition beside an existing call and is
     not separately unit-tested — the same as `Sweep`'s own two call sites
     in `worker.go` have no dedicated "was it called from `start()`" test
     today (`internal/run/sweep_test.go` tests `Runner.Sweep` directly,
     never through `Worker`); `WorkerOptions.Runner` is a concrete
     `*run.Runner` (`internal/run/worker.go:90`), so there is no seam to
     fake a call count against without a refactor this node does not need.
   - **Test**: `internal/run/retention_test.go`, using the package's
     existing `fixture.runner(options ...func(*run.Options)) *run.Runner`
     helper (`internal/run/support_test.go:259`, the same one
     `sweep_test.go` builds its own `Runner` from) — store-backed, this
     package's normal tier. Seal two attempts through `SealAttempt` against
     the fixture's real store, backdate one's `ended_at` past `twin_days`
     (constructing the fixture with an old `ended_at`, or updating it
     through the store the way the attempt naturally reaches it), run
     `f.runner(func(o *run.Options) { o.Retention = run.Policy{TwinDays: 7};
     o.LogDir = dir }).SweepRetention(ctx)`, assert the old one's twin file
     is gone, its frame file is still present, and its frame's row count in
     `activity` is unchanged (`SELECT count(*) FROM activity WHERE
     step_run_id = ...` before and after); the young one is untouched; the
     returned `RetentionReport` counts match. A second case leaves
     `o.Retention` at its zero value with no `RetentionProjects`: asserts
     `SweepRetention` removes nothing, the report is zero, **and** the
     captured log output contains the one "nothing to sweep" line — proving
     the full acceptance criterion, not just the no-op half of it. `go test
     ./internal/run/...` passes.

  the oldest attempt's age, and the resolved policy; against an unmodified
  default config it prints `keep` and the sweep's own log line (from a
  `mill work` run against the same log dir) says "nothing to sweep".
- `make test-acceptance` if the node's acceptance criteria are also driven
  through this suite (matching prior activity-retention nodes' Proof
  sections); otherwise the `test-db` scenarios above stand in for it.

## Risks

- **The `Inspect`-per-run-directory sweep cost.** A host with many run
  directories under `--log-dir` (long-lived worker, rarely swept) pays one
  RPC per distinct `runID` on every sweep pass, even for runs whose every
  attempt is already past compaction and idempotently skipped. Mitigation:
  `compactFrame`'s idempotency check makes a repeat pass cheap on the write
  side; if the `Inspect` volume itself proves to be the bottleneck in
  practice, a future change can skip runs whose every candidate file's own
  st_mtime is younger than the deployment's minimum configured threshold
  before calling `Inspect` at all — deferred rather than built now, since
  it optimizes a cost not yet shown to matter and the acceptance criteria
  say nothing about sweep latency.
- **A frame mid-rewrite when a reader's `Logs` call is serving it.**
  `writeFrame` already writes to `.tmp` then renames, so a concurrent
  `ReadFrame` either sees the old, complete frame or the new, complete one,
  never a partial file — the same crash-safety `SealAttempt` already
  relies on. Risk is only that a `Logs` stream mid-read of the old frame's
  bytes finishes reading the pre-compaction content it started with, which
  is correct (the read started before compaction) rather than a hazard.
- **Frame count/kind check for idempotency mis-firing on a legitimate
  single-record attempt.** An attempt that sealed to exactly one record
  whose kind happens to render as a `Compacted`-shaped case cannot occur
  today (nothing but this node's own compaction ever writes that kind), so
  the idempotency check is safe now; if a future node ever gives the mill
  itself a reason to emit a single-record `Compacted`-kind frame at seal
  time (unlikely — nothing in docs/activity.md proposes one), the check
  would wrongly treat it as already-compacted. Worth a one-line doc comment
  on `compactFrame` if that ever becomes a live concern; not a present risk.
- **`RetentionProjects` naming a project the deployment's `--project` filter
  never claims from.** Silently inert — the sweep only ever encounters
  attempts under runs this worker actually ran, so an override for a
  project this worker never touches is dead configuration, not a bug. Not
  worth validating at startup; `docs/tools.md`'s configuration table entry
  will say so.

## Decisions

- **`renderCompacted` duplicates `logsRenderer`'s two marker cases locally
  in `internal/run/retention.go` instead of sharing code with
  `internal/cli/logs.go`.** `internal/cli` already imports `internal/run`,
  so the reverse import `retention.go` would need is not available without
  moving `logsRenderer` (or its two marker cases) into `internal/run` —
  out of scope for this node and a risk to existing, tested behavior for
  no benefit beyond avoiding ~6 lines of duplication. The two
  implementations can diverge only if a future node changes one marker's
  wording without the other; that risk is accepted as the smaller cost
  against a cross-package refactor of working code, and step 2's test
  pins `renderCompacted`'s output against real `mill logs` output for the
  same input to catch drift at the point compaction happens, not just
  internal self-consistency.
- **Compaction is a new proto oneof case, not a repurposed existing one.**
  Every existing kind either re-summarizes on render (`Text`/`Thinking`) or
  is rendered by a different label (`HarnessStderr`) than a compacted
  attempt's log should carry; a new case is the only shape that renders the
  stored text exactly as given. See Approach's rejected alternatives.
- **The index is never written to by retention**, full stop — not even the
  per-row `truncated`/`bytes` columns `00022_activity.sql` happens to make
  updatable. The work order's "Retention never touches the index" is taken
  as the literal, stronger reading over an alternative where compaction
  updates the index's own `truncated` column to match the frame, because
  the literal reading is what keeps "the index row count for a compacted
  attempt is unchanged" trivially true rather than merely arranged.
  `Logs`'s per-row `truncated` in its response comes from the frame's own
  record (`Truncated: true` on the one `Compacted` record), not the index.
- **Age and project resolution go through the store (`Inspect`), not file
  mtime**, per the rejected mtime alternative in Approach — the store
  already has `ended_at` for free and mtime would need new bookkeeping to
  survive a compaction rewrite.
- **The retention sweep reuses the worker's existing `SweepInterval`/
  `lastSweep` cadence rather than introducing a second timer** — the work
  order says "the sweep interval" (definite article, singular), and
  `internal/run/sweep.go`'s own doc comment already warns against widening
  its scope (mill#49); a second, sibling method called from the same two
  trigger points keeps that boundary intact while still riding the same
  clock.
- **`retention`/`retention-projects` are flat strings in a small grammar,
  not nested YAML**, mirroring `cache-global-cap`/`cache-global-caps` —
  the one existing precedent in `Config` for "a scalar default plus a
  per-name override map" — rather than inventing the first nested shape in
  the file.
- **`mill doctor` gains its own `--log-dir` flag** rather than reading
  `LogDir` only from the config file, matching every other doctor flag
  (`--workspace-dir`, `--sandbox-root`, …), all of which take both a flag
  and a config fallback via the same `unset(cmd, ...)` pattern.
