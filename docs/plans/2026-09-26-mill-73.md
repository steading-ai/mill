# The live tier passes in the guest: lint specs get a budget they can meet and the plugin spec skips a dead socket

## Approach

Two independent, minimal changes in the two files the failures point at, plus a comment recording the measurement the wait's margin is based on. No new abstractions, no new files besides this plan.

**Lint specs → `Serial`.** All five `It`s in `lint_test.go` that invoke `makeTarget(dir, "lint")` (lines 16, 57, 75, 96, 110) get Ginkgo's `Serial` decorator, not only the four the work order names by line number. The work order's four are what happened to lose the scheduling race in mill#70's run; the fifth ("Specs stay in Ginkgo", line 75) calls the identical helper and is exposed to the identical contention — it simply hasn't been caught yet. Decorating only four leaves a fifth spec that can flake on a future run under a different random schedule, which reopens the exact problem this node exists to close. Decorating the container (`Describe`-level `Serial`) was rejected: it would also serialize the cheap, non-timing-sensitive "os/exec is imported only under internal/workspace" grep spec for no reason, diluting what `Serial` is for. Raising the wait, or making it per-target, was rejected because the work order forbids hiding contention behind a bigger number, and the measured cost doesn't need it (see below).

**The wait stays 3 minutes.** `time mise exec -- make lint` on this guest, unloaded, measured **35s real**. Three times that is 105s, under the existing 180s wait — the work order's own fallback applies ("if `Serial` alone brings them under three minutes, keep three"). The change here is a comment on `checkout_test.go`'s wait recording that measurement and the margin, not a new constant. Re-measure at implementation time in case guest conditions have shifted since context-gathering; use whatever number is current.

**Plugin spec → probe before dialing.** `plugin_test.go`'s socket check gets a second guard: after the existing "unset" skip, dial `MILL_SOCKET` with a short timeout (`net.DialTimeout("unix", ..., 200*time.Millisecond)`, mirroring `internal/doctor/doctor.go`'s existing unexported `dialable`), and `Skip("MILL_SOCKET names a socket nothing answers on")` when nothing answers. Rejected: shelling out to `mill status --view refs` and checking its exit code — it spawns a process, and folds the skip condition into that subcommand's whole error surface instead of the one fact that matters (is anything listening). Rejected: exporting `doctor.dialable` for reuse — six lines duplicated locally is cheaper than growing a package whose own doc comment scopes its probes to the process that spawns the sidecar and holds the signing key, not to test helpers in the root package.

## Risks

- **The guest's load during the failing run (48) came partly from other tenants, not just this suite's own 7 parallel procs.** `Serial` isolates the lint specs from *this suite's* parallelism but not from unrelated concurrent load on a shared guest. If the ×3 margin still isn't enough, the next escalation is a bigger fix (e.g. a lint-specific timeout env var, or moving contention-sensitive specs off the shared guest) — out of this node's scope; if it recurs, report it rather than papering over it with a larger constant.
- **Decorating a fifth spec beyond the work order's named four could be read as scope creep.** Mitigated by the approach section's explicit rationale: the mechanism, not the specific four line numbers, is the diagnosed cause, and leaving the fifth spec parallel reopens the same class of flake nondeterministically. If a reviewer disagrees, reverting to exactly the four named specs is a one-line-per-site change.
- **No real running mill is available in this environment to exercise the "developer machine, live socket, spec proceeds normally" path end-to-end.** Covered instead by code review of the added guard (it only adds a new `Skip` branch; the existing dial-and-proceed path is untouched) and by acceptance criterion 4 being a preservation requirement, not new behavior.
- **`Serial` lengthens the suite's wall-clock** (five specs move from running in parallel to running sequentially, roughly +140-175s at the unloaded 35s/spec rate). No ceiling is stated in the work order; deliverable 3 asks the PR to report the guest's actual figure, which is the visibility this risk needs rather than a fix.

## Decisions

- **All five `make lint`-calling specs get `Serial`, not only the four the work order names by line number.** The work order was silent on the fifth spec (`lint_test.go:75`) because it happened not to fail in mill#70's run; taken the smallest option that still closes the diagnosed mechanism rather than only the observed symptom.
- **The 3-minute wait constant is left unchanged**, per the work order's own fallback clause, once measured at 35s (×3 = 105s < 180s); only a comment is added.
- **The plugin probe is a raw `net.DialTimeout` on `MILL_SOCKET`, not a `mill status` subprocess call** — smaller, deterministic, and matches the exact failure text the work order quotes.
- **The probe timeout is 200ms**, taken from `internal/doctor/doctor.go`'s existing `dialable` convention rather than inventing a new figure.
- **No parameterization of `makeTarget`'s wait per target** — `make build` and `make stage-amd64` are untouched since neither was observed contending; adding a per-target budget now would be an abstraction the work order doesn't ask for.
