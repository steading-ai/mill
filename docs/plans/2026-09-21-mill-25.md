# Dollars on every usage total, from the rate table mill applies

## Approach

Price is applied at the `internal/server` handler layer — a new
`server.WithRates(rates)` `StoreServiceOption`, following the exact shape of
the existing `WithMcpServers` option in `internal/server/store_service.go`.
`StoreService`'s `Status`, `ListRuns`, `Inspect`, and `Cost` handlers call a
pure pricing function on the `[]*millv1.ModelTotals` they already build from
`domain.Service` results, filling `Usd`/`Priced` before returning.

Two alternatives were rejected:

- **Pricing inside `internal/store`**, where every `ModelTotals{}` literal is
  currently constructed. Rejected outright: the acceptance criteria run
  `grep -rn "usd\|rate" migrations/ internal/store/` expecting no hits, so a
  rate table or the words "usd"/"rate" cannot live in that package.
- **Pricing inside `internal/domain`**. Viable, and closer to the data, but
  it would require threading a rate table through `domain.Open`/`domain.New`
  and their 2 production and 4 test call sites. `internal/server` needs no
  signature change to `domain.Service` at all — `WithRates` is just one more
  functional option beside `WithMcpServers` — and it's confirmed to cover
  every reader: `mill status`/`cost`/`inspect` and `mill run`'s internal
  lookups (`internal/cli/run.go`, `storeClient(opts.socket)` at lines 329,
  354, 390, 511) all go through `StoreServiceClient`, never `domain.Service`
  directly. Server-layer pricing has no gaps and touches less.

The rate table itself is config, not domain state: it lives in the worker's
YAML (`rates:` key, mirroring the existing `mcp-servers:` key and its
`McpServerConfig`/`configKeys` pattern in `internal/cli/config.go`), with a
packaged default at `/usr/share/mill/rates.yaml` used when the config names
none — loaded the same way `mcp-servers` is, but read unconditionally in
`runServe` (not gated behind `--work`), since a bare `mill serve` still
answers `Status`/`Cost`/`Inspect`.

2. **Rate types and the pure pricing function, in `internal/server`.**
   Files: `internal/server/rates.go` (new), `internal/server/rates_test.go`
   (new).
   Add `type Rate struct { Input, Output, CacheRead, CacheWrite float64 }`
   (dollars per million tokens) and `type Rates map[string]Rate`, keyed by
   the model string as it appears on `ModelTotals.Model` (the resolved id,
   e.g. `claude-sonnet-4-5-20250929`, not a workflow alias like `sonnet`).
   Add a pure function, e.g. `func price(totals []*millv1.ModelTotals, rates
   Rates)`, that for each entry looks up `rates[total.Model]`: on a hit,
   sets `Usd = tokens/1e6 * rate` (summed across the four token kinds against
   their four rates) and `Priced = true`; on a miss, leaves `Usd = 0` and
   `Priced = false`. No wiring into the RPC handlers yet — this step only
   adds the function and proves it standalone, the same way
   `internal/store/cost_internal_test.go` proves `dayKey` standalone with no
   DB.
   Test (Ginkgo, no `db` Label, no fixtures): a total over two models prices
   each by its own rate (assert the exact `Usd` to the cent per entry); a
   model absent from the table gives `Priced == false` and `Usd == 0`
   (distinguishing "no rate" from a legitimately free $0 total).

## Risks

- **`fillByModel` silently drops `Usd`/`Priced`.** Caught by step 5's own
  spec; without it the MODEL section would look unpriced even when STEP is
  correct. Mitigation: the spec in step 5 compares MODEL's sum against
  STEP's directly, not just against a hand-picked constant, so a regression
  here fails loudly.
- **Partial pricing on multi-model RUN/WORKFLOW/STEP rows** (Decisions,
  below) is a judgment call the work order doesn't spell out; a reviewer
  could reasonably want the opposite (dash the whole row if any model is
  unpriced). Mitigation: the rule is stated plainly in `docs/tools.md` and
  is a small, isolated change to swap if rejected.
- **Rewriting `internal/cli/read_test.go`'s exact-string table assertions**
  for the new column is mechanical but easy to under-cover — a header
  changes but a row's column count doesn't, or vice versa. Mitigation:
  `make test-unit` catches any mismatch immediately since these are exact
  string/table comparisons, not snapshot-fuzzy.
- **Published per-token rates are external knowledge**, not derivable from
  the repo, and drift over time. Mitigation: the packaged file is a
  default, explicitly overridable by the operator's own `rates:` config key
  (step 3's fallback order already prefers the configured table); the risk
  is operational, not a defect in this change.
- **Regenerating `gen/` touches the TypeScript output too** (buf generates
  for both Go and the sidecar). Nothing in the sidecar emits `ModelTotals`,
  so this should be a no-op beyond the type gaining two fields, but the diff
  should be checked, not assumed.

## Decisions

- **Where the packaged default lives on disk before packaging**:
  `packaging/rates.yaml`, beside `packaging/config.yaml`, packaged as a
  plain (non-`noreplace`) file — refreshed with the package like
  `/usr/share/mill/workflows`, since it's mill's own default tied to the
  workflows it ships, not an operator override. The work order names only
  the installed path (`/usr/share/mill/rates.yaml`); the source-file
  location and nfpm content type were unspecified.
- **Missing packaged file is not an error**: `loadRates` returns an empty
  table (no rates configured) rather than failing, mirroring `LoadConfig`'s
  existing "absent file is fine, malformed file is an error" rule. The work
  order is silent on this case.
- **Rates are loaded unconditionally in `runServe`**, not gated behind
  `--work` the way the rest of `applyConfig` currently is — because `Status`,
  `Cost`, and `Inspect` are answered by `serve` regardless of `--work`, and
  the work order gives no reason to price only under `--work`.
- **Multi-model bucket rows in `mill cost` sum whichever entries are
  priced**, dashing only when none are, rather than dashing the whole row if
  any single contributing model is unpriced. The work order's "no figure,
  never zero" rule is stated per-model; extending it to mean "dash the whole
  aggregate if any part is unknown" would hide real, known partial cost.
- **`mill inspect`'s top summary line keeps no `USD` figure**, only the
  per-step table gets one — the deliverable explicitly says "per attempt"
  for inspect, and the summary line duplicates what `mill status` already
  shows.
